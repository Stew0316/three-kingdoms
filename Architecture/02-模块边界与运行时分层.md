# 模块边界与运行时分层

状态：提案  
目标：定义完整游戏需要的模块、职责、生命周期和依赖边界。

## 1. 模块总表

| 模块 | 核心职责 | 默认生命周期 | 建议阶段 |
| --- | --- | --- | --- |

| GameFlow | 新游戏、读档、切图、菜单、章节流程 | 游戏进程 | S3 |

| Actor | 单位身份、阵营、属性、资源和组件组合 | 地图或遭遇 | S1–S2 |

| Modifier | Buff、Debuff、权限、叠加、驱散、Tick | 单位 | S2 |

## 2. 全局服务边界

Autoload 只保留真正跨场景且需要单例生命周期的服务，建议候选为：

### 2.1 Bootstrap

- 最早初始化内容包和服务。
- 检查内容版本、基础设置和启动错误。
- 决定进入主菜单、开发沙盒或自动测试场景。

Bootstrap 不保存玩家战斗状态。

### 2.2 ContentRegistry

- 按类型和稳定 ID 查询 Definition。
- 检测重复 ID、缺失依赖和内容包加载顺序。
- 提供只读访问，不向业务暴露可随意修改的 Dictionary。

### 2.3 GameFlow

- 管理主菜单、新游戏、载入、切图和章节流程。
- 使用 `MapId + EntranceId` 进入地图。
- 在切图前协调保存、清理和淡入淡出。

GameFlow 不计算伤害，不运行 AI，也不拥有当前战斗的 Hitbox。

### 2.4 SaveService

- 读取和写入存档 DTO。
- 做版本迁移、备份和损坏检测。
- 不直接读取场景树；由各模块提供可保存快照。

### 2.5 AudioDirector

- 管理音乐、全局音量、Audio Bus 和跨场景音乐过渡。
- 短促的角色音效可以由场景内 Audio Cue 播放器负责。

## 3. 当前地图和遭遇内的服务

以下对象默认不能做全局单例：

- CombatResolver
- EncounterController
- ProjectileSystem
- AreaEffectSystem
- LocalCombatEventQueue
- VfxPool
- TargetQueryService

这些服务应归属于当前地图或遭遇。换图时销毁它们，可以天然清理旧飞行物、旧命中窗口、局部订阅和延迟事件。

## 4. Actor 组件模型

角色根节点建议只负责聚合，不把所有逻辑写入一个巨大 `Combatant`：

```text
Combatant
├─ IdentityComponent
├─ AttributeComponent
├─ ResourceComponent
├─ HealthComponent
├─ CommandReceiver
├─ AbilityComponent
├─ ModifierContainer
├─ MovementComponent
├─ HurtboxComponent
├─ AnimationBridge
├─ AudioEmitter
├─ VfxAnchors
└─ Controller
   ├─ PlayerController
   └─ AIController
```

不是要求立即拆成以上所有节点。拆分判断标准为：

- 有独立生命周期或状态所有权。
- 会被多类单位复用。
- 可以独立测试。
- 修改频率与角色主体不同。
- 已经使 `Combatant` 出现难以维护的条件分支。

简单数值结构可以是普通 C# 对象，不必全部做成 Node。

## 5. Command：统一玩家和 AI 的入口

推荐命令集合：

```text
Move
BasicAttack
Dodge
CastSkill
CancelCast
Interact
UseItem
```

玩家输入和 AI 只负责产生命令，不直接：

- 扣除目标生命。
- 修改技能冷却。
- 绕过沉默或眩晕。
- 直接生成奖励。
- 强制切换成某个战斗状态。

命令接收者统一执行权限、资源、冷却、目标和当前状态检查。Boss 豁免通过 Definition 或明确规则表达。

## 6. AI 分层

AI 建议拆为四层：

1. **感知**：可见目标、距离、方向、障碍和最近事件。
2. **决策**：选择追击、撤退、普攻、技能、换阶段等意图。
3. **命令**：生成与玩家一致的 `MoveCommand`、`CastSkillCommand`。
4. **执行**：交给角色和技能系统校验与执行。

Boss 阶段由 Encounter 或 Boss Phase Controller 管理，阶段切换只改变可用技能、权重、属性修正和演出，不创建另一套战斗规则。

首期不需要完整行为树编辑器。有限状态机、Utility 打分或简单决策表足以支持少量人形敌人。

## 7. 内容注册模块

ContentRegistry 至少按以下类型注册：

```text
Skills
Modifiers
Units
Items
Maps
Encounters
Quests
Dialogues
GameplayCues
AudioCues
ContentPacks
```

注册过程应产生明确错误：

- 重复 ID。
- 引用不存在。
- 内容包缺少依赖。
- 类型不匹配。
- Definition 参数非法。
- 循环依赖。

发布包中严重内容错误应阻止启动或禁用整个问题内容包，不能等玩家进入 Boss 战后才因为空引用崩溃。

## 8. 时间和暂停

继续沿用现有战斗附录中的三时间域：

| 时间域 | 推进内容 | 暂停菜单 | 打击停顿 |
| --- | --- | --- | --- |
| 实际/UI 时间 | 菜单、淡入淡出、提示和停顿恢复 | 继续 | 继续 |
| 战斗时间 | CD、Buff、区域寿命、资源恢复 | 停止 | 默认继续 |
| 单位动作时间 | 前后摇、局部动画、攻击位移 | 停止 | 指定单位停止 |

模块不能各自随意修改 `Engine.TimeScale`。打击停顿和动作加速应通过明确的时间服务或单位动作倍率实现。

## 9. 模块间事件示例

```text
Combat 发出 UnitDefeated
├─ Encounter 判断胜负和波次
├─ Quest 更新“击败魏延”目标
├─ Progression 发放技能或经验
├─ Narrative 设置剧情标记
└─ Presentation 播放死亡和胜利反馈
```

`UnitDefeated` 表示已经发生的事实。任务和表现不能通过取消该事件来撤销死亡；需要拦截伤害或死亡时，应在 Combat 结算阶段使用明确的规则扩展点。

## 10. 暂不建设的模块

以下内容在真实需求出现前不进入核心路线：

- ECS 重构。
- 通用依赖注入容器。
- 完整可视化脚本语言。
- 网络同步与回滚。
- 任意第三方 C# Mod 执行。
- 程序生成任务。
- 无限随机词缀装备系统。
- 为所有对象提供热更新。

它们可能很强，但会显著增加调试、内容迁移和工具维护成本，不能直接等同于扩展性。

## 11. 当前 S1 配置与常量边界

状态：已实现（2026-09-30）。

- `Scripts/Const` 保存编译期固定的技术契约，例如节点名、输入动作名、碰撞层、ZIndex、动画名和固定界面文案。
- `Scripts/Config` 保存 Godot `Resource` 的 C# 类型定义，描述 Inspector 中可以编辑哪些字段。
- `Resources/Config` 保存 `.tres` 配置实例。当前吕布、魏延的生命、移动、受击、击退、打击停顿和四类动作数值均从各自资源读取。
- 场景只引用对应配置资源，不再重复覆盖同一组玩法数值。
- 当前生命、剩余冷却、动作计时等运行时状态继续由节点持有，不写回共享 `.tres`。
- 只服务于单个算法的循环边界、插值系数和临时绘制坐标保留在实现内部；它们不是跨模块契约，也不是策划配置。
