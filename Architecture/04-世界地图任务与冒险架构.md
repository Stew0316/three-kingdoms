# 世界、地图、任务与冒险架构

状态：提案  
目标：支持城镇、野外、洞窟、Boss 房、重访、传送、任务和地图持久状态。

2026-10-02 路线确认：正式地图采用《宝可梦 火红／叶绿》式二维俯视 TileMap，不继续扩展 HD2D 三维关卡。地图与即时战斗共享二维坐标、碰撞和导航；Boss/演武可切入独立二维房间。

## 1. 世界不是一个巨型场景

推荐使用世界图连接多张中小型地图：

```text
WorldGraph
└─ Region：中原
   ├─ Map：起始村
   ├─ Map：后山
   ├─ Map：野外道路一
   ├─ Map：小洞窟
   ├─ Map：小城镇一
   └─ Map：魏延挑战地
```

这样做的好处：

- 单张地图容易编辑、加载、测试和回退。
- 遭遇失败可以重置当前地图，不污染整个世界。
- 不同地图能使用不同环境表现和玩法规则。
- DLC 可以新增 Region 和 Map，而不是修改一张巨大主场景。
- 玩家仍能通过明确出入口形成连续世界的空间记忆。

## 2. MapDefinition 与 MapScene

### 2.1 MapDefinition

只读定义建议包含：

- MapId。
- 显示名称文本键。
- 所属 RegionId。
- PackedScene 引用。
- 地图类型：城镇、野外、洞窟、室内、Boss、剧情。
- 是否允许小地图、坐骑和快速旅行。
- 默认音乐、环境音和色调。
- 入口定义列表。
- 邻接地图信息。
- 推荐等级和内容标签。

### 2.2 MapScene

负责当前地图的物理与表现节点：

```text
MapRoot
├─ Ground
├─ TerrainDetail
├─ Collision
├─ Navigation
├─ Occluders
├─ DecorationsBack
├─ Actors
├─ Interactions
├─ EncounterVolumes
├─ StoryTriggers
├─ VfxWorld
├─ DecorationsFront
└─ CameraBounds
```

场景节点名称可以调整，但职责必须区分。装饰节点不能顺手承担重要任务状态。

正式二维地图建议使用以下 Godot 结构：

```text
MapRoot2D
├─ Ground：TileMapLayer
├─ TerrainDetail：TileMapLayer
├─ Collision：TileMapLayer / StaticBody2D
├─ Navigation：NavigationRegion2D
├─ DecorationsBack：TileMapLayer
├─ Actors：Node2D（Y Sort）
├─ Interactions：Area2D
├─ EncounterVolumes：Area2D
├─ StoryTriggers：Area2D
├─ VfxWorld：Node2D
├─ DecorationsFront：TileMapLayer
└─ CameraBounds：区域数据
```

地图仍按网格制作，但实时战斗角色默认使用连续八方向移动。道路和室内尺寸必须按闪避、突进、横扫及多人形敌人绕行重新设计，不能直接照搬回合制 RPG 的一格宽通道。

## 3. 入口和切图

切图使用稳定标识：

```text
MapId + EntranceId
```

示例：

```text
当前出口：core:map/start_village / exit_east
目标入口：core:map/field_01 / from_start_village
```

切图流程：

1. 玩家进入出口 Trigger。
2. 地图系统验证出口是否解锁。
3. GameFlow 建立切图请求。
4. 当前地图导出可持久化状态。
5. 清理遭遇、投射物、区域和局部事件订阅。
6. 播放淡出或过场。
7. 加载目标地图。
8. 按 EntranceId 定位角色和朝向。
9. 恢复地图持久状态。
10. 播放淡入并恢复控制。

存档不能只记录 Vector2 坐标。地图布局调整后，入口 ID 比绝对位置更稳定。

## 4. 地图持久状态

每张地图只保存需要跨进入保留的状态：

- 已打开的唯一宝箱。
- 已激活的传送点。
- 已完成的一次性遭遇。
- 已触发或已关闭的机关。
- 已采集且需要持久化的资源点。
- NPC 的剧情阶段。
- 已发现的地图区域。
- 可破坏物的必要状态。

临时状态默认不保存：

- 当前投射物。
- Hitbox 和 SkillCast。
- 普通短时 Buff。
- 飘字和粒子。
- 普通敌人的每一帧位置。

普通敌人是否复活由 `SpawnPolicy` 决定，例如重新进图、休息后或章节变化后重置。

## 5. 地图连接和解锁

WorldGraph 表达可达关系，但最终通行由条件决定：

```text
出口存在
+ 剧情条件满足
+ 机关状态满足
+ 当前地图允许离开
→ 可以切图
```

条件例子：

- 完成魏延挑战。
- 获得火折子后允许进入暗洞。
- 激活驿站后允许快速旅行。
- Boss 战中临时封锁出口。
- 剧情打断路线后禁止传送。

旧区域重访应尽量提供新价值，例如新入口、师傅、隐藏道具、剧情变化或利用新技能打开的捷径。

## 6. Encounter 遭遇

EncounterDefinition 建议包含：

- EncounterId。
- 敌人和出生点配置。
- 开始条件。
- 区域封锁规则。
- 波次或 Boss 阶段。
- 胜利和失败条件。
- 奖励定义。
- 是否一次性。
- 重试和重置策略。
- 音乐和演出 Cue。

EncounterController 负责当前运行状态：

```text
Dormant
→ Preparing
→ Running
→ Victory / Defeat
→ Settled
```

首个垂直切片优先使用地图内无缝即时战斗：可见敌人追击、进入战斗范围、封锁必要区域、结算后恢复探索。Boss、演武和需要严格重置的挑战可以加载独立二维战斗房间；两种模式复用同一 `Combatant`、技能配置和伤害结算，不复制一套 HD2D 或 3D 战斗规则。

战斗死亡重试应重建整场遭遇，不能只复活吕布而保留上一轮的投射物、旗阵或 Boss 阶段。

## 7. Interaction 交互系统

统一交互入口：

```text
InteractCommand
→ 查找当前候选交互物
→ CanInteract
→ 执行 InteractionAction
```

交互对象包括：

- NPC 对话。
- 门和出口。
- 宝箱。
- 商店。
- 驿站。
- 训练设施。
- 邮筒和信件。
- 机关。
- 采集点。
- 剧情调查点。

InteractionAction 可以是打开 UI、发出剧情事件、给予物品、设置标记或请求切图。交互对象不应直接找到任务列表并修改内部字段。

## 8. 语义触发器

地图触发器只描述“发生了什么”：

```text
EnterRegion(core:region/village_gate)
Interact(core:object/inn_keeper)
EncounterCleared(core:encounter/weiyan_trial)
ItemAcquired(core:item/fire_lighter)
MapEntered(core:map/field_01)
```

Quest、Narrative、Progression 和 Presentation 分别订阅需要的事实。

避免如下逻辑：

```text
玩家进入 Area2D
→ 找到 HUD/QuestPanel/Task3
→ 把第三行文字改成绿色
→ 直接打开下一张地图
```

这种写法会把地图、任务、UI 和流程永久耦合。

## 9. Quest 任务系统

### 9.1 QuestDefinition

- QuestId。
- 标题、描述和本地化文本键。
- 前置条件。
- 目标图结构。
- 奖励。
- 自动开始和自动结算策略。
- 失败条件。
- 后续任务。

### 9.2 QuestRuntime

- 当前状态。
- 当前目标进度。
- 已选择分支。
- 已领取奖励。
- 必要的任务局部变量。

### 9.3 目标类型

首期支持有限类型：

- 到达地图或区域。
- 与对象交互。
- 完成遭遇。
- 获得或交付物品。
- 设置剧情标记。
- 完成对话选择。

不要把任务进度做成 Buff。任务和 Buff 可以监听同一个击败事件，但生命周期、保存和职责完全不同。

## 10. Narrative 剧情系统

剧情系统负责：

- 对话节点和选择。
- 角色立绘或场景内说话者。
- 剧情条件和标记。
- 请求镜头、角色移动和演出 Cue。
- 分支结果。

剧情演出需要可取消和可恢复的边界：

- 切图和死亡时清理临时演出状态。
- 关键进度标记在安全提交点写入。
- 对话文本使用本地化 Key。
- 场景角色引用通过当前地图的 ActorId 解析，不写死绝对 NodePath。

## 11. 城镇、营地与外出循环

### 11.1 城镇/营地

承担：

- 技能配置和强化。
- 训练与收益上限。
- 商店、医馆、铁匠和驿站。
- 主支线对话。
- 安全保存。
- 快速旅行。

### 11.2 野外

承担：

- 路线选择。
- 普通遭遇。
- 材料和隐藏点。
- 小型剧情。
- 通向地标和 Boss 区域。

### 11.3 地标和 Boss 区域

承担：

- 独特机制。
- 技能导师或技能奖励。
- 明确的挑战与重试点。
- 高质量特效和演出。

## 12. 快速旅行

快速旅行目标使用 `MapId + EntranceId`。解锁条件建议为：

- 玩家已经到访该城市。
- 激活驿站或左慈传送点。
- 当前不在战斗或剧情封锁状态。
- 当前章节没有禁止该线路。

旅行系统不复制一套地图列表，而是查询 WorldGraph 中已激活并带 FastTravel 标签的入口。

## 13. 地图校验标准

每张正式地图进入内容包前至少检查：

- 每个 EntranceId 唯一。
- 每个出口的目标地图和入口存在。
- 玩家出生点不在碰撞体内。
- 关键 NPC 和交互对象 ActorId 唯一。
- Boss 房有失败重置和离开策略。
- 封锁区域不会在异常中断后永久关闭。
- 导航和碰撞没有明显死角。
- 可持久化对象拥有稳定 PersistentId。
- 地图允许/禁止坐骑、小地图、快速旅行的规则已配置。
- 地图在没有装饰特效时仍能完成主流程。
