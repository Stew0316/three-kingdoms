## 1. 基本原则

战斗系统产出事实，表现系统解释并呈现事实：

```text
规则事实
→ Gameplay Cue
→ VFX / Animation / Audio / Camera / UI
```

例如一次暴击：

```text
DamageResult(IsCritical = true, ActualDamage = 38)
→ core:cue/heavy_critical_hit
→ 大型命中火花 + 更强震屏 + 暴击音效 + 暴击飘字
```

禁止反向依赖：

- 粒子播放结束不能决定伤害何时结算。
- 音效未加载不能阻止技能提交。
- 动画丢帧不能漏掉 HitGroup。
- 画质设置关闭装饰粒子不能削弱技能范围。
- Cue 不能直接修改生命和 Buff。

## 2. Gameplay Cue

### 2.1 Cue 请求

建议字段：

```text
CueId
SourceUnitId
TargetUnitId
WorldPosition
Direction
AttachPoint
Intensity
ColorVariant
CastId
LifetimeOverride
```

并非每个 Cue 都需要全部字段。Cue 请求使用普通只读数据，表现层负责把 UnitId 解析为当前场景节点。

### 2.2 Cue Definition

建议包含：

- CueId。
- VFX PackedScene。
- AudioCueId。
- 附着方式。
- Z 层策略。
- 生命周期。
- 是否跟随来源或目标。
- 是否允许池化。
- 画质等级。
- 是否触发镜头反馈。
- 同类 Cue 的并发上限。

### 2.3 Cue 命名

```text
core:cue/halberd_slash_cast
core:cue/halberd_slash_hit
core:cue/tornado_loop
core:cue/tornado_end
core:cue/stunned_status
core:cue/boss_phase_change
```

同一技能的施法、飞行、命中和结束应是不同 Cue，避免一个巨大特效场景承担所有阶段。

## 3. 特效分类

### 3.1 前摇和危险提示

- 蓄力光。
- Boss 抬手。
- 地面危险区域。
- 射线预瞄。
- 即将落点的阴影或标记。

目标是可读性。Boss 高伤技能必须先确保提示清楚，再追求华丽。

### 3.2 动作轨迹

- 方天画戟刀光。
- 弧形或直线拖尾。
- 冲刺残影。
- 分身幻影。
- 投射物轨迹。

动作轨迹使用技能提交时锁定的方向快照，不能读取角色后来改变的朝向。

### 3.3 命中反馈

- 命中火花、血光或尘土。
- 受击闪白。
- 局部打击停顿。
- 镜头震动。
- 音效分层。
- 伤害、暴击、免疫和格挡飘字。

命中反馈必须读取 DamageResult，未造成实际效果时使用 Miss、Immune 或 Block 的专用反馈。

### 3.4 持续状态

- 中毒、燃烧。
- 护盾、霸体。
- 沉默、眩晕。
- 奋起或赛亚人式外圈。
- 脚下光环。

状态视觉由 ModifierInstance 的创建、层数变化和移除事件驱动。相同 Cue 的多来源叠加需要明确是共享一个表现、改变强度，还是每个来源独立显示。

### 3.5 持续区域

- 火场。
- 龙卷风。
- 插地旗阵。
- 治疗或增益光环。
- 雷区、射线阵列。

区域场景可以同时拥有碰撞和表现子节点，但规则寿命由 EffectInstance 控制，粒子只是跟随。

### 3.6 演出效果

- Boss 登场。
- 慢镜头。
- 气势波纹和压迫感。
- 武器名称逐字点亮。
- 城池和大地图转场。

演出 Cue 允许请求镜头和 UI，但需要有超时和取消清理，不能因为动画事件丢失而永久锁定玩家输入。

## 4. VFX 场景约定

推荐结构：

```text
VfxRoot
├─ Visuals
│  ├─ AnimatedSprite2D
│  ├─ GPUParticles2D
│  ├─ Line2D
│  └─ ShaderSprite
├─ OptionalLight
├─ OptionalAudio
└─ LifetimeController
```

约定：

- 默认原点表示命中点或附着点。
- 默认朝右，运行时按 Direction 旋转或镜像。
- 不在 VFX 脚本中查找敌人和造成伤害。
- 使用明确的 Z 分类，不靠大量任意数字叠加。
- 生命周期必须有明确上限。
- 编辑器预览与实机播放使用相同参数来源。

## 5. 2D 技术选择

| 技术 | 适用内容 |
| --- | --- |
| AnimatedSprite2D | 手绘逐帧刀光、爆炸、烟雾 |
| GPUParticles2D | 火星、尘土、持续烟、能量粒子 |
| Line2D | 射线、闪电、轨迹、速度线 |
| CanvasItem Shader | 闪白、溶解、轮廓、波纹、色偏 |
| MultiMeshInstance2D | 大量相似装饰对象，确有性能需求时 |
| Trail/采样点 | 刀光拖尾、快速移动残影 |
| BackBuffer/屏幕 Shader | 少量关键演出的扭曲、冲击波 |

当前项目是 640×360 视口，所有特效必须在实际视口和像素缩放下检查，不能只在高分辨率编辑器预览中判断效果。

## 6. 刀光设计

刀光至少由以下语义参数控制：

- 起始角、结束角。
- 内外半径。
- 持续时间。
- 颜色渐变。
- 宽度曲线。
- 透明度曲线。
- 是否跟随武器节点。
- 是否产生残影和火星。

玩法范围与刀光视觉范围需要接近，但两者不能共享同一个碰撞对象。调动画或材质时不能意外改变攻击判定。

## 7. 光环设计

光环由两个部分组成：

- 规则部分：Area Effect 或 Modifier 提供范围、队伍、Tick、进出区域规则。
- 表现部分：脚下圆环、符文、粒子、角色外圈或 UI 状态。

应处理：

- 多个相同光环的叠加规则。
- 光环来源死亡后的移除。
- 角色离开范围时的延迟或立即失效。
- 画质降低时保留核心范围提示。

## 8. 打击停顿与镜头

### 8.1 Hit Stop

- 优先冻结攻击者和受击者的单位动作时间。
- UI 和停顿恢复计时继续运行。
- 从 30–50ms 试起。
- 连续命中设置上限，避免长时间卡顿。
- 普通小兵、Boss、霸体目标可有不同倍率。

### 8.2 Camera Impulse

请求参数：

- 强度。
- 持续时间。
- 方向。
- 频率。
- 衰减曲线。
- 优先级。

多个震动请求由 CameraDirector 合成和限幅，技能不能各自直接重置摄像机位置。

### 8.3 慢镜头

只用于关键击杀、Boss 阶段和剧情演出。慢镜头需要明确：

- 影响战斗时间还是单位动作时间。
- UI 是否继续。
- 音效音高是否变化。
- 如何保证恢复。

## 9. 音频架构

建议 Audio Bus：

```text
Master
├─ Music
├─ SFX
│  ├─ Combat
│  ├─ UI
│  └─ Environment
└─ Voice
```

AudioCueDefinition 可以配置：

- 一组随机变体。
- 音量和音高范围。
- 同类并发上限。
- 最短重复间隔。
- 2D 空间衰减。
- 所属 Bus。

连续多段攻击需要并发限制，避免音效叠加成噪声。

## 10. 动画桥接

Gameplay 不直接操作具体动画名，而是请求语义动作：

```text
Idle
Move
BasicAttack
SkillCast
Hurt
Dodge
Dead
```

角色的 AnimationBridge 把语义动作解析为实际 AnimationPlayer、AnimatedSprite2D 或状态机参数。技能时间线决定规则时点，动画事件可以用于纯表现 Cue，但不能成为唯一伤害来源。

## 11. 性能和降级

优化顺序：

1. 先在目标设备记录帧时间和峰值对象数。
2. 限制同类 Cue 并发。
3. 降低装饰粒子数量和 Shader 采样。
4. 对高频、短生命周期对象实施池化。
5. 对远处或屏外效果降级。

不建议一开始把全部特效池化。池化会引入重置状态、Signal 残留、材质共享和生命周期错误，只有高频效果通过分析确认有收益时再加入。

## 12. 表现验收清单

- 前摇提示先于伤害生效。
- 刀光方向、位移方向和判定方向一致。
- 命中反馈基于 DamageResult。
- 暂停、死亡和切图后没有残留循环特效和音效。
- 特效关闭或丢失时规则仍正常。
- 光环和持续区域在低画质仍能看清范围。
- 角色共用材质时，闪白不会永久修改其他角色。
- 同屏大量命中不会造成不可接受的卡顿和音频爆炸。
- 所有镜头和输入锁定都存在可靠的取消与超时恢复。
