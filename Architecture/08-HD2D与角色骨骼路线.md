# HD-2D 与角色骨骼路线

日期：2026-09-30。

状态：**HD2D 三维演武场已实现；16 关节拆件骨架接入已实现，人物拆件生图因网络故障未完成，当前使用旧图蒙皮回退。**

## 最新落地结构（2026-09-30）

默认入口为 `Scene/HD2DArena.tscn`，继承原 `Arena`，以 `Hd2D` 开关添加 `Hd2DStage`。旧 `Scene/Arena.tscn` 继续用于二维规则对照。

- 保留唯一 CharacterBody2D / Area2D 物理世界；三维地台是表现对象，没有重复三维碰撞。将 XY 平面以 0.02 比例映射到 XZ。此阶段二维逻辑足以表达无高低差演武场；未来可行走台阶/跳跃才迁移物理接口。
- 每名角色两个独立透明 SubViewport：人物与飘字为竖直 Sprite3D，光环/预警/刀光为水平 PlaneMesh。初始化后将 Rig、Feedback、Trail 重挂到各视口，组件保留已绑定宿主引用；HUD 通过 Combatant.Rig 访问，不依赖旧节点路径。
- 固定 Camera3D、实体墙柱、台阶、灯光阴影、雾与辉光。264 块地砖用 MultiMesh 共享网格与材质，避免反复重开制造大量材质。
- `CharacterPresentationConfig` 分离美术图集、光环半径/色彩、粒子模式、残影间隔/寿命；修改它们不改变伤害。
- `CharacterRig` 建立 16 关节和独立 AtlasTexture 图层，包含双节持柄 IK、大幅挥击和平滑过渡。未设置 PartsAtlas 时自动使用 `LegacyPortraitRig`；生图失败不能冒充大幅动作美术已交付。
- 移动残影复制人物视口当前图像，保留世界位置；单人样板最多约五张并存。CPU/GPU 读回存在成本，扩展多人群场景前需纹理池和实测，不应原样给所有小兵开启。
- 当前旋转使用镜像压缩和环形轨迹表现，没有背面素材；不是完整四向转身动画。现有写实图也不是传统像素 HD2D 定稿。

完整需求、已完成项、失败的生图记录与验证边界见 [本轮记录](../Demand/Prompt/2026.9.30-HD2D演武场与被动技能.md)。下文保留之前的路线分析，涉及“尚未实现三维”的描述为历史状态。

## 需求及范围

原始问题与澄清答复完整记录于 [需求记录](../Demand/Prompt/2026.9.30-角色尺寸骨骼刀光与HD2D.md)。用户最终明确想要 HD-2D 感觉，不按全三维角色与自由跟随镜头来理解。

目标是二维人物与三维环境结合：固定斜俯视镜头、实体地形高度、前后遮挡、受控灯光与阴影、适量景深和雾。当前写实人物是验证骨骼的临时资源；是否最终转为像素角色尚未明确，不能直接认定当前写实图已经满足传统 HD-2D 风格。

## 可行性与主要成本

Godot 可实现这种技术组合。就当前单人开发规模，建议先做一间小演武场的三维视觉验证，不同时扩地图、任务和装备。

| 事项 | 可复用部分 | 新工作 |
| --- | --- | --- |
| 战斗 | 生命、伤害数据、前后摇、冷却和 AI 决策思路 | 现有逻辑耦合 CharacterBody2D，需提取状态和输入接口 |
| 角色 | 原图、骨骼和动作曲线 | 表现层从读取父 Combatant 改为读取状态快照，接入三维显示 |
| 场景 | 出生、结算、重开流程 | 三维地面、墙体、遮挡物、材质与灯光 |
| 移动和命中 | 距离与扇形规则 | CharacterBody3D / Area3D、XZ 平面移动和镜头相对输入 |
| 特效 | 时序、角度、半径、渐隐参数 | 三维平面网格或粒子，匹配世界坐标和遮挡 |
| 美术 | 武将身份与配色 | 风格样板、分层人物、四向动作、场景素材一致性 |

判断：一间技术样板是中等难度；达到完整商业游戏那样稳定的美术品质，主要成本在素材制作、光照调校、遮挡和动画，而不只是换一个相机。不能通过开启某个“2.5D 模式”自动获得这种效果。

## 推荐的三维样板

1. 独立建立 HD2D 演武场，保留已验证的二维场景用于对照。
2. 使用固定 Camera3D、地面及少量墙柱，先确认二维人物的比例、脚底和遮挡。
3. 静态人物用 Sprite3D；骨骼人物由透明 SubViewport 渲染二维 Rig，再将 ViewportTexture 显示在三维竖直面片上。每个角色视口需要独立生命周期与性能预算，不能无上限复制。
4. 确认方向约定、像素过滤/连续过滤、透明排序、阴影与受光方案，再迁移 XZ 平面的移动和命中。二维 Node2D.Y 与三维高度 Y 不能直接等同；地面深度映射至 Z。
5. 保留规则层的施法时钟，由表现层读取动作和方向，逐项跑胜负、重开、暂停、贴墙和命中回归。
6. 最后添加克制的辉光、景深与雾；不能让景深模糊正在交战的角色或危险预警。

不建议长期同时维护两套位置与碰撞世界，否则可见角色、命中盒和导航容易失配。

## 本轮二维表现的实际结构

```text
Combatant（现有战斗根）
├─ Visual（静态资源入口，运行时隐藏）
├─ Rig：CharacterRig
│  ├─ Skeleton2D / 八根 Bone2D
│  ├─ Skin：Polygon2D / UV / 骨骼权重
│  ├─ AnimationPlayer（运行时生成动作曲线）
│  └─ BoneOverlay（F4 调试）
└─ WeaponTrail（只读动作状态与锁定方向）
```

这是局部表现桥接的已实现起点，并非已完成通用 Gameplay Cue 总线。角色只额外暴露 `VisualTime` 与 `CastDirection`，蒙皮和刀光不修改生命、碰撞或冷却。关闭刀光的伤害等价性已纳入自动验证。

单张 PNG 蒙皮不能完成独立武器挥舞和真实转身。正式制作应先拆分并补齐遮挡部分，建立持械关节链，再用 AnimationPlayer 编辑姿态；是否引入外部骨骼工具应等一套完整动作验证后决定。
