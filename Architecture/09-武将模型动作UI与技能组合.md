# 武将模型、动作、UI 与技能组合

日期：2026-10-11。状态：下述当前子集已实现并通过回归；长期技能/Modifier 内核仍按03号文档演进。

## 1. 用户目标与边界

用户希望未来支持很多武将，每个武将拥有自己的外观绑定、动作与界面资料，技能像其提出的 OMG 玩法方向一样可以交换。本文件定义本项目的组合方式，不推断其他游戏的内部实现。

独立的是武将内容资源与运行时所有权。骨架求解、伤害结算、技能执行和 HUD 控件继续共用基础代码，避免复制整套控制器。添加普通新武将不应在公共骨架里增加武将名或风格枚举分支。

## 2. 已实现的装配关系

```text
武将场景 Components/Characters/*.tscn
├─ Config：CombatantConfig（身体基础属性）
├─ Presentation：CharacterPresentationConfig
│  ├─ Model：CharacterModelConfig（该武将的模型绑定）
│  ├─ Animation：CharacterAnimationConfig（该武将的动作集）
│  │  ├─ StandingPose / MovingPose / DodgePose
│  │  ├─ 受击参数与路程步态
│  │  └─ Basic / Dash / Sweep / Counter：CharacterActionAnimationConfig
│  │     └─ Windup / High / Contact / Follow + 归一化阶段时点
│  └─ 光环 / 粒子 / 残影参数
├─ Ui：CharacterUiConfig（身份、名称、界面主题、头像引用）
├─ Loadout：SkillLoadoutConfig（默认主动槽与被动装备）
│  └─ Resources/Config/Skills 中的独立技能定义
└─ Controller（玩家输入或距离AI，负责提交命令）

运行时 Combatant.Skills：SkillLoadoutRuntime
├─ 单位自己的装备槽
├─ 单位自己的被动列表
└─ 单位自己的 SkillId → 剩余冷却
```

| 配置或状态 | 所有权 | 交换技能时的行为 |
| --- | --- | --- |
| `*-model.tres` | 武将内容资源 | 图集、头发、武器、骨架绑定保持自身配置 |
| `*-animation.tres`、动作曲线与姿态 | 武将内容资源 | 继续用自身动作解释借入技能的语义 |
| `*-ui.tres` | 武将内容资源 | 武将姓名与界面主题不变 |
| `<hero>.tres` 基础属性 | 武将内容资源 | 生命、移速、击退等不随技能交换 |
| `Config/Skills/*.tres` | 可共享的只读技能定义 | 数值、名称、ID及动作语义跟随技能 |
| `*-loadout.tres` | 默认装备内容资源 | 当前实例换装不改写默认值 |
| `SkillLoadoutRuntime` | 每个单位实例独占 | 当前装备改变；冷却按技能ID保留 |
| `AttackSpec`、`CurrentMotion` | 本次施法快照 | 施法开始后不随装备变化 |

## 3. 模型绑定和魏延盔缨

`CharacterModelConfig` 保存图集、采样区、16个业务关节的父节点局部位置、16个拆件的显示范围、绘制顺序、腿长、镜像与独立配件等。当前骨架属于16关节人形约定，公共求解器支持这套约定；不是任意拓扑骨架编辑器。

魏延头部原图包含完整盔缨。旧头部区域 `(83,85,218,237)` 截去了顶部，再按公共冠顶位置叠加第四行的独立盔缨，导致根部和轮廓不对。魏延模型现改为：

- 头部采样第一格 `(0,0,313,322)`，实际透明包围盒约 `(13,5,281,315)`。
- 头部局部显示范围 `Rect2(-10.5,-18,16,22)`。
- `CrestVisible=false`，保留完整头图里的单束盔缨，随头骨移动和镜像。
- 吕布仍使用自己的 v4 双翎配件、原根部挂点和显示尺寸。

原图没有改写。本轮魏延盔缨与头部合为一张拆件，不再单独摆动；若后续要求独立发丝动力学，需要专门提供无盔缨头图和可挂接的独立盔缨素材。

## 4. 输入槽、技能语义与动作

`CombatAction.Basic/Dash/Sweep/Dodge` 保留旧输入槽名称，分别对应J、K、L和空格。它们只表示玩家按了哪个槽。`CombatActionConfig.Motion` 请求 `CombatMotion`，由当前武将的 `CharacterAnimationConfig` 映射到动作资源。

例如把魏延横扫装进吕布的K槽：

```text
K输入 → 查当前K槽 → 魏延横扫规则
                     ├─ 伤害18、前摇0.65、CD6秒
                     ├─ Motion=Sweep → 吕布的 Sweep 动作曲线
                     └─ HUD显示“转腰横扫”与该技能剩余CD
```

原先 `HalberdSweep/GuardedGlaive` 枚举和公共采样器内的武将角度分支已移除。动作差异保存为各自姿态与 `CharacterActionAnimationConfig` 的时点参数；求解器统一处理关键点插值和双手握点。

技能规则时间继续决定前摇、生效、后摇。动画按归一化比例适配这些时间，不能因素材或动画长度变化修改伤害窗口。当前 `CombatMotion.Dodge` 仍对应既有闪避执行状态；未来投射物、引导等新执行机制应由独立效果处理器扩展，不能只增加一个动画名称就视为支持了该技能。

## 5. 配置与运行时换装

编辑默认装备：打开武将的 `*-loadout.tres`，将槽位引用改为其他武将或新建技能资源即可，无需换模型、动作集或控制器。

运行时示例：

```csharp
var borrowed = GD.Load<CombatActionConfig>("res://Resources/Config/Skills/weiyan-sweep.tres");
bool changed = actor.TryEquipSkill(CombatAction.Dash, borrowed);
```

换被动使用 `actor.TryEquipPassive(index, passiveDefinition)`。当前只替换已有槽位，不包含新增被动槽、删除槽位或完整选技界面。

约束：

- 仅空闲/行走且没有正在播放的反击时允许换装，攻击、闪避、受击、死亡或结算时拒绝。
- 同一单位不能在两个主动槽重复装入同一 `SkillId`；被动列表同样按ID去重。
- 卸下的技能继续保留并推进该单位的冷却，重新装备后不会刷新；两个单位使用相同技能定义仍各自计时。
- 改动当前实例只替换运行时引用，不写回 `.tres`、默认Loadout、他人状态或正在施放的快照。
- ID必须唯一且非空。制作新技能应新建独立资源和稳定ID；同一技能的多份拷贝不能随意赋同ID却采用不同规则。
- 当前没有保存装备到存档；重开仍按默认Loadout初始化。

## 6. UI 和 AI

武将名称、名称色、血条色和被动区颜色来自独立 `CharacterUiConfig`。角色身份不会跟着借入技能改变。HUD仍共享控件与布局，当前技能名称、被动说明和冷却来自运行时装备；长被动文案限制在各自区域内，悬停可查看全文。

`Portrait` 与技能 `Icon` 目前是资源接口，本轮文字HUD没有新增头像/图标控件或专属布局场景。后续特殊武将面板可在共用HUD之外增加独立视图，不应把身份判断写进战斗规则。

现有距离AI通过当前装备的 `CombatMotion` 寻找可用槽位，再读取其范围、位移和冷却。技能互换或换槽后仍能通过统一施法入口执行。控制器类名暂时保留 `WeiYanController` 以兼容现有场景和调试读取，其技能选择逻辑已不依赖武将身份。

## 7. 新增武将流程

1. 新建自己的模型配置：图集、关节绑定、采样、拆件范围和配件。先独立检查头部、武器与左右脚，不继承吕布的视觉挂点假设。
2. 新建自己的动作集：站立、行走、闪避、受击，以及当前支持的普攻/突进/范围攻击/反击语义；可以复用求解算法，姿态资源由自己引用。
3. 新建自己的UI配置和基础属性；按需建立新的默认Loadout，技能可以直接引用现有Skills目录中的定义。
4. 在武将场景上分别引用以上资源，绑定玩家控制器或AI控制器；身份不由IsEnemy决定。
5. 验收自身动作、镜像、握点、暂停、受击，并至少借入另一个武将的一项主动和被动技能验证组合。
