# 冒险会话与交互架构

日期：2026-10-24。状态：现有小规模实现的系统边界；完整任务定义图和通用地图注册仍属 [世界架构提案](04-世界地图任务与冒险架构.md)。

## 会话与场景

`AdventureSession` 是跨场景冒险数据入口，持有只读配置、`AdventureProgress`、按稳定 ID 唯一的人物数据、返场入口与遭遇模式。它不持有当前人物 Node、Hitbox、投射物或战斗结算器。

人物属性在首次创建时复制一次，后续冒险场景引用同一人物数据，不在每次进图重新叠加成长。当前持久生命字段与人物所有权见 [全局人物架构](14-全局人物数据与地图菜单.md)。独立战斗沙盒使用可重置数据，不污染冒险存档。

当前场景负责角色节点、地图几何、交互对象、局部界面和碰撞的装配与销毁。返场使用稳定入口标识；具体入口、任务、奖励、服务价格与训练值见 [首城内容](../Demand/Content/FirstCity.md)。

## 交互和进度提交

`InteractionQuery` 统一候选目标距离排序与世界遮挡查询。场景提供资格和过滤条件，不能通过菜单或快捷栏绕过当前行动、模态对话、距离、遮挡和切图检查。

交互对象提供稳定 ID 和语义动作，界面负责显示选项与结果，不直接维护第二份任务进度。进度提交使用幂等方法：接取、完成与领奖分别检查状态；重复事件不能重复发放奖励。持续交互在完成时提交收益，取消和中断不能提前发放。

任务只消费符合模式和目标条件的遭遇事实；练习沙盒、失败与撤退不会被当作正式成功。内容场景可以决定自身任务目标，通用结算器不硬编码人物名称。

## 成长、战斗与骑乘边界

成长修改人物自己的运行时属性或明确的伤害倍率，不写回共享配置。技能快照与伤害结算仍经过战斗模块。短时状态和冷却当前随战斗节点重建，不能在文档中误写为已实现全冒险冷却持久化。

骑乘资格、速度、上下马与碰撞由宿主玩法管理；动作和外观由 [坐骑组件](13-马匹组件与动作复用.md) 读取移动事实。通用坐骑组件不查询任务或写存档。

## 保存与边界

`AdventureSaveStore` 保存版本与普通数据，临时文件写完后替换正式文件；失败必须显示真实结果。场景节点、动作时钟和临时效果不序列化。旧档缺省字段与未知内容 ID 要有明确处理策略。

当前是类型化的小规模进度和显式切图，不是通用 `QuestDefinition`、事件总线或完整 `WorldGraph`。扩展时由实际重复需求驱动，避免让单个内容场景承担全世界规则。

测试隔离正式存档，检查跨图重复成长、幂等奖励、取消、失败返回及旧档兼容。实际结果保留在 [内容实现索引](../Demand/Content/ImplementationIndex.md) 和对应 `Demand/Prompt`。
