## 2026-10-14 入口统一与生命平衡

移除首城试炼在Arena中强制关闭GroupPractice的分支，直接演武与城门进入均默认四人同场。首城仍固定玩家吕布与魏延任务身份并提供回城按钮；魏延死亡即可完成任务，其余对手存活时整场继续，三名对手全灭才是演武胜利。这样不会为了让关羽、刘备出场而把原任务改成必须击败三人。

基础生命调整为吕布1200、魏延/关羽/刘备1000。冒险训练仍在实例叠加，保留存档生命比例；三次训练后吕布1390。旧章节中的5000血量和城门单挑为历史记录，以本段为准。需求与验证见 [入口与血量修复](../Demand/Prompt/2026.10.14-演武入口四人统一与血量调整.md)。

## 入口与生命周期

`GameEntry.tscn`为默认入口，正常运行切到`FirstCity.tscn`；`--arena`及旧战斗/动作专项参数进入原`Arena.tscn`。`--city-test`进入城市并挂载跨场景测试器。

`AdventureSession`是本次唯一新增Autoload，持有只读`FirstCityConfig`、可保存`AdventureProgress`、任务遭遇模式及返城入口标识`inn/gate`。它不持有当前人物、Hitbox、冷却或Resolver。城市/演武场拥有自己的角色实例和碰撞节点，切图销毁旧局部状态。

## 职责

| 类型 | 职责 |
| --- | --- |
| FirstCityConfig / first-city.tres | 城名、徒步与两匹马速度、训练收益及上限、锻造成本和奖励的只读参数 |
| AdventureProgress | 任务状态、训练次数、锻造、货币、兵书、地形标记；幂等的接取/完成/领奖/破坏方法 |
| AdventureSession | 加载进度、提交保存、切图、注入冒险属性、转发遭遇成功事实 |
| AdventureSaveStore | 显式路径的版本化JSON读写；临时文件完成后再替换正式文件，返回错误 |
| FirstCity | 装配人物/设施/界面，统一读取输入、最近交互查询、派发服务和操作反馈 |
| CityMap / CityBuilding / CityTree / CityArtAtlas | 地面与公共景物、世界物理边界、独立建筑/树木表现及透明图集取样；物理与地图状态分离 |
| CityInteractable | 稳定ContentId、名字、位置与交互高亮；不保存任务进度 |
| CityDialogue | 通用标题、正文、选项回调、焦点及关闭；不查询任务或改动Buff |
| CityHorse / CharacterRig.Riding | 马身四蹄动画与武将原拆件的骑乘求解，不决定马速和成长 |

## 任务与地形

任务阶段：`Available → Accepted → Completed → Rewarded`。接取解锁崩击；只在任务遭遇胜利后发送`EncounterCleared("core:encounter/weiyan_trial")`，由Progress检查目标ID与阶段。回城交付后才发兵书和货币。直接打普通演武、未接任务的胜利、败北或撤回均不推进任务。已完成、已领奖不会重复结算。

巨石与木匣使用稳定交互ID`boulder/cache`。交互距离48像素，检测到世界遮挡则拒绝。巨石北侧唯一入口的物理通道在破坏后移除，重建城市根据`BoulderBroken`还原；`CacheClaimed`保证隐藏奖励一次性。训练在4秒结束时提交收益而非点按钮就提交，三次收益递减且不因休息/切图重置。

目前是具体任务状态机和类型化方法，不是完整QuestDefinition目标图、通用事件总线或全世界地图注册表。后续增加第二城时再提炼地图与入口资源，避免以当前小城控制器承载所有世界逻辑。

## 成长与战斗边界

城市创建玩家及任务演武场`_EnterTree`时，先用`HeroCatalog`装配，再复制该实例的`CombatantConfig`注入最大生命。敌人和共享资源保持原值。`ProgressionDamageMultiplier`为实例属性，默认1；`CombatResolver`只在敌对直接攻击中乘入此值，固定反伤/反击保持原规则。

任务场使用同一Arena场景、人物、控制器、技能和Resolver，只关闭`GroupPractice`，固定吕布对魏延并隐藏选将按钮，避免任务目标被换走。正常独立演武场仍为四人模式。

返回城市保存实际生命比例；战败返回`inn`入口，生命比例25%。每个新遭遇重建冷却/短时状态。驿站免费恢复生命；不是复活当前Dead状态实例，而是回城创建新的存活角色。

## 骑乘边界

`IsMounted`与`ExplorationSpeedOverride`是Combatant实例状态。城市通过两个配置速度注入移动逻辑，仍使用`MoveAndSlide`和归一化八方向输入。马不增加第二个会推挤骑手的身体，碰撞足迹复用人物的脚底圆形。

骑乘沿用武将原拆件与固定骨长，覆写为坐姿的脚/手目标、双手执缰，隐藏主副兵器并保留身份配件。`WalkDistance`驱动马腿相位及骑手上下起伏，顶墙不累计假步长。下马恢复原参考姿态分支与武器显示，进战斗自动下马。当前实现左右朝向镜像，不包含八向独立马匹贴图与骑战。

## 存档与验证

`user://first-city-v1.json`只保存普通进度字段和版本，不写Godot节点引用。主要服务提交、任务推进和切图时保存；重启从驿站附近安全入口进入，不记录每帧绝对位置。读档校验版本、枚举和数值范围，失败会显示提示。文件写入失败不会伪称保存成功。

所有测试参数使用新的内存会话，不读正式存档；磁盘验收使用`res://Build/first-city/isolated-save.json`。`--city-test`跨城市/演武真实节点、UI按钮、物理步与伤害队列，涵盖成功和失败路线。原战斗81项与四人演武53项回归通过。

首城初版美术为程序绘制的可替换原型：地面实际使用TileMapLayer，其余由独立表现节点绘制。可替换图集及NPC素材而不改任务/存档规则；没有覆盖已有角色PNG。

## 2026-10-13：首城表现分层与古城美术

本轮按用户指定更新表现目标：建筑、地形采用《清明上河图》的市井古城气质，人物与房屋的比例、道路与入口的可读性参考火红／叶绿；仍是三国题材的二维俯视地图。美术约束已写入根目录`AGENTS.md`，原始需求与参考来源见`Demand/Prompt/2026.10.13-首城清明上河图风格与建筑比例.md`。

正式规范入口为`Source/StyleGuide/城池与地形风格指南.md`；`AGENTS.md`要求AI每次开始任务先阅读，再按实际工作遵守适用章节。后续增加屋顶、灯笼、门面和器物差异时，沿用指南的统一透视、光照、比例与五屋用途区分；这些差异属于建筑表现参数或图集内容，不应进入任务与存档状态。

`CityMap`负责地面TileMap、公共景物、街巷与世界碰撞；`CityBuilding`从地图文件拆为独立表现文件，本轮接入资源更新为`Source/City/HuaiAn/huai-an-buildings-qingming-v2.png`，v1原图保留。`Scripts/Presentation/CityArtAtlas.cs`处理三列两行透明图集：先用各物体的自定义窗口隔离内容，再收紧透明边界，避免跨平均分格线的檐角被裁断或串入邻格。建筑图片以统一的落地基准绑定，显示轮廓与已有物理足迹分别维护；更换屋顶、墙面或招牌时，不应重新编写任务、NPC服务或存档规则。

2026-10-14补充：屋顶、灯具和门面按五屋用途形成不同结构；酒字布幌、铸造锤标与交叉刀剑门饰由`CityBuilding`表现层绘制，依附现有梁柱和门框。字牌由引擎排字，纹理已有的灯具不重复叠加。驿站服务继续由原交互点派发，兼酒肆外观不引入第六栋建筑或新服务类型。表现窗口和标牌尺寸均不进入`AdventureProgress`。

地面与建筑属于当前场景的表现层，不能写入`AdventureProgress`，不增加新的Autoload。原有城门、巨石和隐藏路的有效通道、马厩可进入范围与门前交互距离继续作为玩法约束；任何显示尺度变化都需检查这些边界。NPC、马匹和角色骨架继续复用，图集不包含会决定任务状态的文字或碰撞数据。

2026-10-14实机调整：城市镜头缩放0.85、观察目标向北95像素，为北侧屋顶让出HUD空间；马厩展示马脚点528、缩放0.8并同步交互点，骑乘仍使用玩家挂载的独立坐骑表现。该视图调整不保存到进度。v2接入后编译通过，真实图形首城59项回归通过，日志与截图见`Build/first-city-v2`。

## 2026-10-14：坐骑步态与外观拆分

`HorseAppearance`与两份`horse-chestnut/horse-dapple.tres`分别定义体形宽度、毛色、长短鬃、白额/斑纹、皮囊与鞍毯；马厩展示和玩家骑乘绑定同一匹的只读外观。速度仍由`FirstCityConfig`的190/250提供，外观资源不持有速度或进度。

`CityHorse`持有本实例的步态相位、起停权重、朝向与马背起伏。96像素实际路程为一轮，对角腿同相；支撑期落蹄后蹬、回摆期抬蹄，远近腿分层。它以ProcessPriority=-10先更新，`CharacterRig.Riding`再读取相同状态，消除独立起伏时钟的错位；换马上马重置距离基线。原生几何直接绘制并补充轮廓，不新增中间视口或改变全局纹理过滤。仍为左右侧身镜像配合八方向移动，不代表实现八向独立贴图。

`--horse-test`由GameEntry路由首城，隔离存档并验证93项，输出连续骑乘帧至`Build/horses`。原有首城60项回归通过。需求与验收见`Demand/Prompt/2026.10.14-骑马步态清晰度与独立外观.md`。
