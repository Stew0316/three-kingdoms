日期：2026-10-17。状态：已实现；本轮验证见 [整理需求与验收](../Demand/Prompt/2026.10.17-项目结构整理与三国自然风格规范.md)。本文描述实际代码组织；其他架构文档的未来模块仍按提案理解。

2026-10-21 补充：根级 `剧本` 保存故事、章节和对白；`Scripts/UI/Navigation` 保存共用侧栏、天下图及小地图。`AdventureSession` 唯一持有全局配置与冒险人物数据，属性在人物首次出现时复制一次并跨图复用；世界图内容存于 `Resources/Config/WorldMap`。详见 [导航架构](14-全局人物数据与地图菜单.md)。

## 定义、配置与运行时

| 位置 | 内容 | 不放在这里的内容 |
| --- | --- | --- |
| `Scripts/Definitions/Constants` | 输入、节点名、碰撞层、文案、场景路径和稳定 ID 等技术契约 | 当前生命、任务进度、冷却计时 |
| `Scripts/Definitions/Combat` | 输入槽、动作语义、伤害类型等固定枚举 | 每次施法快照、伤害请求 |
| `Scripts/Definitions/Animation` | 固定业务关节、父链及旧资源默认绑定 | 动画时钟、骨骼实例 |
| `Scripts/Definitions/Catalogs` | 武将内容寻址和统一装配、内置马匹外观寻址与只读资源持有 | 玩家选择等可变状态 |
| `Scripts/Definitions/World` | 地图固定布局、房间和烛台 ID | 当前地图节点、已点燃集合 |
| `Scripts/Config` | 按 Characters、Combat、Items、World 分类的 Godot Resource 类型 | 资源实例和运行时对象 |
| `Resources/Config` | `.tres` 可编辑数据，Characters 下按武将归组，Animation 下保存动作与姿态 | 每局不断变化的状态 |
| `Scripts/Combat` | 施法快照、伤害请求、装备/状态运行时与结算 | 武将图集和造型差异 |
| `Scripts/World/State` | 冒险会话、进度、存档与选将状态 | 共享资源定义 |

纯静态不等于常量：`InteractionQuery`、动画曲线和 IK 是算法，属于各自领域；运行时只读的 `AttackSpec` 和 `DamageInfo` 是本次施法/命中的数据，也不归入静态内容目录。只在一个算法内使用的插值系数与临时坐标留在实现旁，避免制造失去上下文的常量总表。

`HeroSelection` 独立保存玩家与对手选择；`HeroCatalog` 原属性保留兼容转发，默认装备读取通过 `LoadDefaultLoadout` 复用统一路径。运行时不能改写 `GD.Load` 返回的共享配置；冒险成长在复制的单位配置上应用。

## 场景与地图

```text
Scripts/
  Bootstrap/          启动与开发入口路由
  Characters/         单位、输入与行为入口
  AI/                 敌方决策
  Encounters/         演武场装配、流程与结算
  World/
    City/             首城地图、场景、交互编排与 HUD 片段
    Cave/             洞窟地图与场景
    Shared/           共用交互目标、近距查询和墙体创建
    State/            跨图状态、存档和选将
  UI/
    Adventure/        对话、行囊和城镇导览
    Combat/           战斗 HUD
    Common/           样式与主题工厂
  Legacy/             保留旧场景引用的早期角色脚本
  Tests/              按 Animation、Combat、World 分类的现有验收
  Tools/              项目专用的资源引用检查
```

`FirstCity` 分为场景生命周期、交互对话、HUD 三个 partial 文件，共享同一个实例，没有新增管理器或状态副本。`CityMap` 保留装配、TileMap 与碰撞，绘制方法放在 `CityMap.Drawing`；建筑与树的独立绘制归入环境表现，`CityOverview` 从首城场景类移入 UI。

`InteractionQuery` 共用距离排序与世界遮挡射线：首城传入已破巨石/已领奖宝箱过滤及目标末端容差；洞窟严格要求射线无遮挡。`WorldGeometry` 由同一矩形创建墙体与可选遮光多边形。两处复用保留各地图的交互语义和碰撞轮廓。

`UiStyles` 每次创建独立样式，避免共享可变主题；战斗样式沿用默认边距，城镇对话显式传入原边距。

## 骨骼与表现

| 位置 | 职责 |
| --- | --- |
| `Presentation/Rig/CharacterRig.cs` | 生命周期、实例字段与逐帧调度 |
| `CharacterRig.Binding` / `Artwork` | 骨架构建、图集裁剪、贴图及材质绑定 |
| `CharacterRig.Attachments` | 靴掌、副武器等配件同步 |
| `CharacterRig.ReferencePoses` | 读取姿态与动作资源、按规则时钟采样 |
| `CharacterRig.Walking` | 实际路程驱动的步态、足底与重心 |
| `CharacterRig.Kinematics` | 姿态目标、固定骨长和握点解算 |
| `CharacterRig.Riding` | 读取同帧坐骑姿态，保持骑手与鞍、缰绳联系 |
| `CharacterRig.FallbackPoses` | 旧模型兼容动作，独立于正式关键姿态 |
| `Presentation/Animation` | 无状态的两节骨链数学、平滑与 Catmull-Rom 插值 |
| `Presentation/Mounts` | 独立马入口、动作时钟、步态采样、连续蒙皮、骑乘配件与玩法适配 |
| `Presentation/Effects` | 刀光、残影、地面效果与火焰照明 |
| `Presentation/Environment` | 城镇图集采样、建筑与树木表现 |
| `Presentation/Legacy` | 历史 HD-2D 桥接和旧立绘骨架 |

仍是同一个 `CharacterRig` 类型和 16 关节业务约定，partial 只分离职责。固定骨架默认数组按实例创建，可编辑资源保持独立；IK 不持有 Node 或动作时钟。公共求解保留原有骨长、弯曲支路、目标钳位和握点约定，不把角色身份分支塞回算法。

骨架装配完成立即应用零时间站姿并同步拆件，消除首个处理帧之前的直臂绑定姿态；动作时钟和技能规则不因此推进。

马匹可复用场景位于 `Components/Mounts`，独立演示位于 `Scene/Examples`。完整入口组合动作、外观与骑乘连接；`CityHorse` 仅适配现有人物，通用组件不引用城市和战斗玩法。马的固定父链归入 `Definitions/Animation`，内置外观目录归入 `Definitions/Catalogs`，实例时钟与蒙皮归入表现层，详见 [马匹组件架构](13-马匹组件与动作复用.md)。

## 迁移与维护约定

- 移动脚本时一并移动已有 `.uid`，保留 C# 类型名、资源导出属性名和枚举序号；更新场景、资源、Autoload 与代码中的路径。
- 武将的原有文件名、玩法数值、技能 ID 和存档字段保持不变；旧存档继续由版本 1 读取，不因物理目录变化迁移内容 ID。
- 二维主场景与历史样板均保留；历史脚本放入 Legacy，不删除仍被场景引用的入口。
- `BaseSource` 与 `addons` 是独立子模块，本轮不改其历史通用工具；新的游戏专用公共代码留在所属领域。
- 验证使用 `python Scripts/Tools/verify_resources.py`、C# 编译、Godot 资源导入与对应专项回归。静态检查不解析插值构造路径，武将切换等动态路径由运行时验收覆盖。
- 本轮根级目录保持不变。`AGENTS.md` 只描述一级职责和长期规则；子目录、函数、数值、资产与验收变化更新这里或对应专题。
