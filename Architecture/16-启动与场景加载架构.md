# 启动与场景加载架构

日期：2026-10-24。状态：以下启动流程已接入；通用内容预载清单仍是后续扩展方向。

## 职责与边界

`Scripts/Bootstrap/GameEntry.cs` 选择入口、请求场景与依赖资源、查询加载结果并切换场景。`Scripts/UI/Common/StartupSplash.cs` 管理启动覆盖层、错误显示与切换后的释放。启动器不保存角色状态、不决定地图碰撞、任务或外景布局。

启动页文案、品牌素材、字号和布局属于界面内容，见 [启动表现与雪山历史记录](../Demand/Content/Records/StartupAndSnowMountainHistory.md)；具体地图外景见 [雪山外景](../Demand/Content/SnowMountain.md)。

## 加载流程

1. 解析正常游戏、开发预览和验证入口。
2. 创建独立 CanvasLayer 覆盖层，先提交画面再发起加载。
3. 使用 `ResourceLoader.LoadThreadedRequest` 逐项请求目标场景及其依赖；逐帧查询状态并持有已加载的资源句柄。
4. 必要资源就绪且最短展示条件满足后切换；加载耗时超过展示条件时，不额外追加等待。
5. 切换前把覆盖层交给根节点；覆盖层等待 `SceneChanged` 和目标场景首个绘制帧后自行释放，避免入口节点销毁时暴露装配过程。
6. 请求、资源或切换失败时保留覆盖层并报告错误，不伪称加载成功。

人物场景交由目标场景正常创建，避免重复线程预载引入原生资源清理问题。错误、退出和正常完成都需要解除信号与绘制事件订阅。

## 路由与所有权

正常启动和场景预览经过同一启动流程；专项自动验证可以显式跳过装饰展示，但必须保留验证真正启动流程的独立入口。返回已运行的冒险地图不自动重播进程启动页。

目标场景拥有角色、碰撞、局部灯光与局部 UI。启动器只保留加载期间所需资源和进度，不形成另一个冒险会话或全局地图实例。

## 当前限制与演进

当前路由和部分内容依赖仍直接登记在 `GameEntry`，并非通用内容注册或加载清单系统。后续多地图需要复用时，可把目标及依赖清单迁入内容配置；本轮没有实现该提案，也没有改变既有场景入口。

验证应覆盖首次绘制、正常完成、资源失败、切换失败、覆盖层订阅释放、专项路由及重返场景。实际命令、截图和结果见 [内容验证入口](../Demand/Content/ImplementationIndex.md#验证入口) 与 [当次需求记录](../Demand/Prompt/2026.10.24-启动页与城外雪山.md)。
