# RPG设计

> 冒险类游戏

## 概述

- 地形设计应搜索古代城池名字与现在的城市相对应，并参考其地形，如城池核心区与郊区还有交叉点，现代化的部分剪掉然后用其他地方拼凑
- 核心地图为三国类型的三分天下，周围被海洋包裹，有未知岛屿与极地，只有一个大陆，类似异大陆的世界观，地形目前只想到了沙漠城市和绿地，雪山是否加入未知，部分地区有湖水？可以考虑加入湖水中的战斗，核心城镇可以参考三国群英传的城池，使用类似宝可梦的地图设置，大地图相连这样，天气系统可以考虑加入，雪地可以加入脚印等，也可以加入war3伊利丹的火焰脚印效果，或者是在某个角色上，或者在某个物品上
- 人力有限，还需要学习的部分成本，预设从曹操的区域开始，部分城镇可以有海洋内容，前期只做中原内容

## 打击感（重要）

> 来源：知乎“打击感”帖子

1. **命中特效**：当打击成功时加入短暂的闪光、粒子效果或血液飞溅等视觉元素，以即时向玩家反馈“命中”的结果。这些特效应该快速且具有冲击力，不宜干扰玩家视线，但足以强化打击的力量感。
   - 可以做一个简单的击退效果，类似小游戏的那种击退闪光的效果，或者做个简单僵直
2. **打击前的预备动作**：在攻击之前略微增加角色的预备动作，让打击的过程显得更有张力与节奏感。同时，加入轻微的硬直，让每一次命中都显得更有力度。
3. **反馈动作**：敌人被攻击时的反应动画至关重要，简单的僵直或退后动作可以让打击显得更有分量。调整这些反馈动作的时间和幅度，使得敌人受到攻击的感觉既不会太夸张也不会显得轻飘
4. **时间停止与时间缩放**：短暂的时间停止可以让玩家在攻击命中时感受到瞬间的力量反馈，尤其是重要的关键打击，时间缩放（慢动作）可以在击败敌人时使用，以强化成就感。
5. **动作速度差异**：适当增加打击动作和普通动作之间的速度差异，使得打击的瞬间显得更为迅捷和凌厉，可以在攻击瞬间增加动画播放速度，在回收动作时则减慢速度，以营造一种节奏感。
6. **图像后期**：如果技术允许，为画面做后期处理，比如动态模糊、视觉扭曲、血污等，可以显著提高代入感，从而提升打击感。

## 伤害设计

> 参考：https://zhuanlan.zhihu.com/p/416805924

从代码意义上来说，就是一个数据，从攻击者和受伤害者身上的buff和debuff流转一遍，最后完成计算，实际需要一个`DamageInfo`的数据进行双方的流转，因为攻击可能是对双方都是有影响的，像是刃甲或者其他方式

```text
DamageInfo {
    attacker: 可能为空，因为可能是其他来源的伤害，比如天气或者地形或者陷阱
    defender: 承受攻击者，必须有一个gameobject承接这个，不然没有意义，如果死亡可以考虑删除该条数据（恶趣味可以不删）
    tags: 伤害源的数组，是枚举的字符串，标记着类型，比如直接伤害，生命移除，无视某一个类型的护甲等，或者是间歇伤害，可以理解为buff和debuff的标记
    damage: 伤害数据结构，可能设计了多个多重类型伤害，比如火焰，雷电，但是可能会涉及到抗性，所以不能全额减去，也有可能是物理和魔法伤害，但是双边伤害可能是不一致的
    damageDegree: 伤害角度，需要考虑出手成功的角度，出手成功是哪一个角度就是哪一个角度，用来给马尔斯的正面抵挡和刚被猪的背面减伤这样做预留
    criticalRate: 最终暴击率，类似于线性叠加还是乘数叠加，如果没有可以砍掉
    hitRate: 下次攻击必定暴击，与暴击率区分
    addBuffs: 类似于二次伤害的buff，有后置伤害，需要挂起，优先级需要做处理，可能会出现马上生效的问题，考虑做一个list，进行后置添加Damage和buff
}
```

## Skill

1. 实际技能使用timeline来做比较好，就是一个时间线操作：
   a. 准备释放技能
   b. 是否满足条件
   i. 不满足，释放失败
   ii. 满足的话查询身上的buff，进行buff计算（包括debuff）
   iii. 产生timeline，对影响对象进行状态的修改
   iv. 扣除释放的cost，（0消耗一般也需要转cd等，cd也算花费）
   v. 结束释放
2. 对象结构

```text
SkillObj {
    // 此处model是技能的实体，需要挂载到
    skillModel {
        condition: 是否满足条件
        cost: 花费资源
        effect: 释放成功的timeline
        buff: 被动的技能带来的效果
    }
    level: 技能等级，可能会影响到model的效果，比如多个，如果想要多重效果的话，可以参考升级此处
    other: 其他一些需要的数据，预留，可以放入一个数据和一个struct或者interface
}
```

3. AI：ai实际上可以不用学习技能，直接释放技能，如果固定技能，可以考虑直接创建一个skillobj释放

## Buff

1. buff 应该是一个class而不是一个object，任务也可以用buff来，比如击败怪物数量，使用buff来更新
2. buff应该有一个中间件，addbuffinfo来修改buff，使用中间件来修改buff的增删改查
3. buff可能会涉及到一些权限，比如是否可以移动，是否被沉默，或者doom类禁用物品
4. buff需要回调（类似生命周期的效果）
   - **OnOccur**：在BuffObj被创建、或者已经存在的BuffObj层数发生变化（但结果并不小于等于0）的时候，会出触发的脚本
   - **OnRemoved**：在一个buff因为生命周期结束，或者层数<=0的时候，他要被移除掉之前，会执行的一个脚本（可能会涉及到驱散，驱散里可能会涉及到驱散类型，比如强驱散或者弱驱散的dota类型）
   - **OnTick**：每一次触发，每一次跳动即“间歇性效果”，如毒镖之类的
   - **OnCast**：角色释放技能的时候发生的回调（会涉及到动作的操作权限，某些权限会被关闭）
   - **OnHit**：技能在“命中”时候执行的一个回调点，此处的“命中”并不是最终结果的命中的意思，他更像是“碰撞到了”的意思，也就是当有一个DamageInfo的时候就有一次“命中”了
   - **OnBeHurt**：受到攻击时候触发的逻辑，如果说OnHit是主动攻击的效果，那么BeHurt就是被动挨打时候的效果
   - **OnKill**：确定会击败对手的时候执行的回调，在这个回调点实现的主要效果比如“击败任何敌人后都会获得1个金币”、“击败敌人时任务进度提升”、“击败敌人时会发生爆炸对周围敌人产生伤害”等等效果（看起来和onbekilled很像）
   - **OnBeKilled**：在确定会被击败之后执行的回调，死亡爆炸的效果或者是死亡传递或者是瘟疫效果等

5. buff有些是不可见的，没有ui效果，有ui效果的占少数

### 1. 角色

- **伙伴1**：是个女性角色，陪伴主角成长，等主角到了大地方与主角分道扬镳，主角在某一次事件中寒了她的心（是否设计成经济事件？），自此只有邮件联系，并且事件后越来越少，在某一个时刻挺身挡刀，死在主角面前（感觉有点刀）
- **伙伴2**：是个老师，中年人，只教主角一些基础属性的东西，后续去了某个城市，然后一直在城市里呆着教别人，可以在某个阶段再教主角一次核心的东西
- **妈妈**：一直在家等着，还帮忙照顾宠物，喂一喂马，可以做一个类似于徐庶的妈妈被拐的剧情，需要去某个城市的地牢救老妈，可以教一些简单的菜谱，初始的火折子就是妈妈给的

- **伙伴3**：类似陈宫之于曹操的感觉，很有力量，但是后续分道扬镳，可能会和女性角色冲突，实际设计的时候二选一
- **大boss**：有两种路线，第一种路线是打败了大boss，然后发现是大boss的替身，或者像让子弹飞那样，真的被杀了，假的替真的过日子，这种时候需要提前刻画一些习惯，做一些反差来暗示玩家这个是假的，适用于大boss，不适用于小boss；第二种就是杀了某一个boss，发现有另一个角色慢慢变成了boss，适用于这个角色来当最后boss，类似与威震天的黑化，可以考虑用董卓这种偏反派人物刻画，玩家会期待董卓什么时候黑化，可以黑化的出其不意，也可以黑化的顺其自然。这样刻画难度会比较高，但是剧情会比较出彩机会比较大
- **武将**：因为三国时期，没有绝对的正义与邪恶，每个人都为自己，所以应该都是有血有肉的人，反派也应该是讲仗义的，也有非常小人的，可以做一些类似索隆的路痴属性的那种反差感来
- **要不要加入龙**：感觉大家还是比较喜欢龙的，感觉龙的压迫感，适合做反派，也可以某个角色前期温和，后期性情大变，实际是龙在搞鬼。可以做为最后的隐藏 BOSS，类似杨戬那样的压迫感
- **父亲**：做一个父亲的角色，不一定是主角的父亲，中国人对父亲都是很含蓄的，可以做配角的父亲，笼罩一个形象出来，也可以是义父，最后关头才揭晓是义父，这一块不用花很多心思
