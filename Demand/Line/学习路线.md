# 三国动作对战学习路线

目标不是立刻做完整的三国 RPG，而是在 Godot 4.7.1 C# 中完成一个可反复游玩的“吕布对魏延”小型对战场。第一版只需要一个测试场地、两名角色、基础攻击、两个技能、血量，以及能主动和玩家交手的敌人。游历、地图、装备、Buff、任务和复杂 Timeline 都放到后面。

## 最终小目标

做出一个 `Arena.tscn`：

- 玩家控制吕布：移动、朝向、普通攻击、技能 1、技能 2、受击、死亡。
- 魏延由简单的行为树驱动：发现吕布、靠近、在攻击距离内攻击、技能冷却好时施放技能、受击和死亡。
- 双方先各有两个技能：普通近战攻击、一个冲刺/突进技能、一个范围技能。这里“两个技能”建议先指冲刺和范围技能；普通攻击不算在内。
- HUD 显示双方血条；一方血量归零后显示胜负并可重新开始。

完成时不要求美术资源。先用颜色不同的胶囊、方块或临时精灵验证玩法；美术替换必须在动作、判定和 AI 已经稳定后再做。

## 基本原则

1. 一次只解决一个问题。每个阶段完成后都必须能运行、能验证，再进入下一阶段。
2. 先做“手感正确”，再做“架构优雅”。不要在还不能攻击时实现完整 Buff、装备、任务或通用时间轴。
3. 同一个战斗规则由玩家与敌人共用。吕布和魏延应都使用 `Combatant`、`Health`、`Hitbox`、`Hurtbox` 和 `Skill`，区别只在输入来源：玩家输入或 AI 决策。
4. 不要一开始制作行为树插件。先手写一个最小行为树；理解它以后再决定是否抽象成通用节点。
5. 每次遇到问题都写一条“现象、原因猜测、验证结果”笔记。游戏开发最重要的能力之一，是把肉眼看见的问题变成可以调试的状态。

## 推荐项目结构

从第一天开始建立下面的目录，但只在用到时才创建文件：

```text
res://
  scenes/
    arena/Arena.tscn
    characters/LvBu.tscn
    characters/WeiYan.tscn
  scripts/
    characters/
    combat/
    ai/
    ui/
  resources/
    skills/
  art/
    placeholder/
```

命名建议：场景使用 PascalCase，C# 类使用 PascalCase，私有字段使用 `_camelCase`。Godot 的节点名也用清晰的职责名，例如 `AnimationPlayer`、`Hurtbox`、`AttackHitbox`，不要用 `Node2D2`。

## 阶段 0：认识 Godot 和 C# 工作流

### 要学什么

- Godot 编辑器：场景树、Inspector、节点、信号、输入映射、调试器、远程场景树。
- C# 脚本：`_Ready()`、`_Process(double delta)`、`_PhysicsProcess(double delta)`、`[Export]`、`[ExportGroup]`、`GetNode<T>()`、信号连接。
- 2D 角色常用节点：`CharacterBody2D`、`CollisionShape2D`、`AnimatedSprite2D` 或 `Sprite2D`、`AnimationPlayer`、`Area2D`、`Camera2D`。

### 本阶段练习

新建一个空的 2D 项目，在一个场景中放置静态地面、一个 `CharacterBody2D` 和一个 `Camera2D`。给角色挂 C# 脚本，在 `_PhysicsProcess` 中打印一行日志，并在 Inspector 暴露一个移动速度字段。

### 通过标准

你能解释“节点、场景、脚本、信号”各是什么；能运行项目、在调试器看到日志，并能修改 Inspector 的数值影响运行结果。

## 阶段 1：吕布能移动

### 要做什么

1. 在 Input Map 添加 `move_left`、`move_right`、`move_up`、`move_down`，绑定 WASD 和方向键。
2. 创建 `LvBu.tscn`，根节点用 `CharacterBody2D`，加临时显示节点和碰撞体。
3. 在 `_PhysicsProcess` 读取二维输入，归一化后设置 `Velocity`，调用 `MoveAndSlide()`。
4. 根据最后一个非零移动方向保存 `FacingDirection`。后面的攻击、受击和技能都会用到它。
5. 在 `Arena.tscn` 放墙体碰撞，让吕布不能走出场地。

### 这一步真正要理解的事

- 移动和碰撞应在 `_PhysicsProcess`，因为 Godot 的物理帧有稳定节奏。
- 对角移动必须归一化，否则斜向会比直线更快。
- “朝向”与“当前位置”是不同状态；停止移动时仍应该保留最后朝向。

### 通过标准

吕布在场地中稳定移动、与墙碰撞、镜头跟随；停止时面朝最后移动方向。先不要做动画。

## 阶段 2：把吕布做成可观察的状态机

### 要做什么

建立最小状态枚举：`Idle`、`Move`、`Attack`、`Hurt`、`Dead`。先只让 `Idle` 与 `Move` 正确切换，并在屏幕左上角显示当前状态。

### 关键约束

- 状态切换集中在一个 `SetState` 方法，不要让各处代码直接改状态。
- 只有 `Idle` 和 `Move` 可接受移动输入；以后 `Attack`、`Hurt`、`Dead` 会锁定或限制输入。
- 先使用 `AnimationPlayer` 的空动画或计时器占位，之后再替换为真实角色动画。

### 通过标准

能从远程场景树和 HUD 看出当前状态；移动时为 `Move`，停止时为 `Idle`，并且状态不会在一帧中反复跳动。

## 阶段 3：普通攻击与伤害判定

### 要做什么

1. 为吕布增加 `attack` 输入，例如 J 或鼠标左键。
2. 在角色下建立 `AttackHitbox`（`Area2D`）与 `Hurtbox`（`Area2D`），两者使用不同 collision layer/mask。
3. 攻击开始时进入 `Attack`，播放约 0.35 秒的占位动画；只在中间约 0.10 秒启用 `AttackHitbox`。
4. 目标的 `Hurtbox` 收到命中时调用统一的 `TakeDamage(DamageInfo info)`。
5. 建立最小 `Health` 组件：最大生命、当前生命、受伤信号、死亡信号。

### 最小 DamageInfo

先只保留攻击者、伤害数值、击退方向。属性克制、暴击、Buff 标签等都暂不实现。

```csharp
public readonly record struct DamageInfo(
    Node2D Attacker,
    int Amount,
    Vector2 KnockbackDirection
);
```

### 常见错误

- 攻击盒整段攻击动画都开着，导致一次挥砍多次命中。
- 直接用角色之间距离扣血，导致无法处理攻击方向和命中窗口。
- `Area2D` 的 layer/mask 没配置，导致信号从未触发。

### 通过标准

场上放一个不会移动的木桩；吕布朝向木桩攻击时，木桩只掉一次血、短暂变色或后退。未朝向木桩则不命中。

## 阶段 4：受击、击退、死亡与血条

### 要做什么

- 为 `Hurt` 增加 0.15 到 0.25 秒的受击锁定；受击期间用短暂闪白或颜色变化反馈。
- 基于 `DamageInfo.KnockbackDirection` 产生击退速度，并在物理帧里逐渐衰减。
- 生命归零进入 `Dead`，关闭碰撞与行动逻辑，但保留尸体显示。
- 使用 `ProgressBar` 制作吕布与魏延血条，并监听 `Health` 信号刷新。
- 增加重新开始按钮或 R 键重载 `Arena.tscn`。

### 通过标准

连续攻击木桩时，能看见一次一闪、一次扣血、一次击退；血量归零后不能再受伤或行动，并且可以重新开始。

## 阶段 5：让魏延拥有与吕布相同的战斗能力

### 要做什么

复制临时角色场景为 `WeiYan.tscn`，或抽出 `Combatant.tscn` 作为共同基础。此时魏延不需要 AI，只要能被摆在地图中、被攻击、受击、死亡。

### 结构目标

- `Combatant`：状态机、朝向、`Health`、命中盒、受击盒和公共动画接口。
- `LvBuController`：读取玩家输入，要求 `Combatant` 移动或攻击。
- `WeiYanController`：之后读取 AI 决策，要求同一个 `Combatant` 移动或攻击。

不要让 `WeiYanController` 直接修改血量或直接操作吕布节点；伤害必须经过同一套 `Hitbox -> Hurtbox -> Health` 流程。

### 通过标准

把控制器暂时挂到魏延身上也能操控他；这说明角色能力没有绑死在“玩家”上。

## 阶段 6：最小 AI，先不用完整行为树

### 要做什么

先实现一个只有三个分支的决策器：

```text
如果吕布已死亡：停止
否则如果距离大于攻击距离：朝吕布移动
否则：面朝吕布并普通攻击
```

每隔 0.1 秒决策一次，而不是每帧切换动作。加一个小圆圈或 Debug 标签显示魏延当前决策：`Chase`、`Attack`、`Idle`。

### 通过标准

开始游戏后，魏延会追向吕布；接近后停在合适距离攻击；吕布走开后魏延继续追；魏延死亡后停止决策。

## 阶段 7：把最小 AI 重构为行为树

当阶段 6 稳定后，再把同样逻辑改为行为树。行为树不是魔法 AI，而是把“条件判断”和“动作”组合起来的结构。

```text
Selector
├── Sequence：目标死亡 -> Stop
├── Sequence：距离大于攻击距离 -> Chase
└── Sequence：目标在攻击距离内 -> FaceTarget -> BasicAttack
```

### 最小实现建议

- `BehaviorStatus`：`Success`、`Failure`、`Running`。
- `BehaviorNode.Tick(double delta)`：每 0.1 秒执行一次。
- 第一版只实现 `Selector`、`Sequence`、`Condition`、`Action` 四种节点。
- 把黑板数据控制在 `Target`、`DistanceToTarget`、`LastKnownPosition`、`CanUseSkill` 这几项。

### 通过标准

行为树与阶段 6 的表现完全一致，并且调试输出能显示本次执行的是哪条分支。先验证“等价重构”，不要边重构边增加新行为。

## 阶段 8：技能一，冲刺或突进

先给双方做一个容易验证的技能：向当前朝向快速冲刺。吕布可用 K 释放；魏延在距离略远于普攻距离、技能冷却完成时有概率使用。

### 技能统一生命周期

```text
CanUse -> Prepare -> Active -> Recover -> Cooldown
```

- `CanUse`：角色不在 `Hurt`、`Dead` 等禁止状态，且冷却结束。
- `Prepare`：短暂前摇，可以取消移动。
- `Active`：真正位移或开启判定。
- `Recover`：后摇，避免无限连招。
- `Cooldown`：只负责何时可再次使用。

### 通过标准

冲刺有前摇、位移、后摇和冷却；撞墙不会穿出场景；魏延不会反复无间隔冲刺。

## 阶段 9：技能二，范围攻击

双方第二个技能建议做范围攻击：吕布使用方天画戟横扫，魏延使用短时间范围斩。先不做投射物和复杂特效。

### 要做什么

- 复用普通攻击的 `Hitbox` / `Hurtbox` 机制，只改变范围、伤害、前后摇和冷却。
- 一个目标在一次技能内最多受伤一次。为每次施放维护已命中目标集合，技能结束清空。
- AI 只在合适距离、冷却完成、且普通攻击不可用或有机会命中时施放。

### 通过标准

技能范围明显大于普攻；单次挥扫不会一帧扣多次血；魏延能在合理时机使用，而不是随机乱放。

## 阶段 10：一场完整而可调试的对战

把目前的测试内容整合成第一版对战循环：

```text
加载 Arena
  -> 吕布与魏延出生
  -> 追逐、普攻、两种技能、受击
  -> 一方死亡
  -> 显示胜负
  -> R 键重新开始
```

这个阶段只做平衡与修错：调整血量、伤害、攻击距离、攻击前摇、后摇、冷却和 AI 决策间隔。不要加入新系统。

### 推荐初始数值

| 项目 | 吕布 | 魏延 |
| --- | ---: | ---: |
| 生命 | 120 | 100 |
| 移动速度 | 250 | 220 |
| 普攻伤害 | 12 | 10 |
| 普攻前摇/后摇 | 0.12s / 0.23s | 0.16s / 0.26s |
| 冲刺冷却 | 3.0s | 4.0s |
| 范围技能冷却 | 5.0s | 6.0s |

这些数值只是方便观察的起点，不是最终平衡。每次只改一项，并记录改动前后的对战感受。

## 学习顺序与资料使用方法

优先学习官方文档和小型可运行示例，顺序如下：

1. Godot 的“第一个 2D 游戏”和 C# 基础脚本。
2. `CharacterBody2D` 移动与碰撞。
3. `Area2D`、碰撞层和信号。
4. `AnimationPlayer` 的动画轨道、方法调用轨道和状态切换。
5. `Resource` 保存技能配置。
6. 行为树的 Selector、Sequence、Condition、Action 概念。

每学习一个主题，先在独立小场景里做 20 到 50 行的小实验，再带入正式项目。例如先做“两个圆形 Area2D 命中一次”的实验，不要第一次接触碰撞层就同时调试吕布、魏延、动画和 AI。

## 暂时不要做的内容

在完成阶段 10 前，明确不做：

- 大地图、游历、城镇、任务、存档、装备、随机掉落。
- 多角色、多武器、多段连招、空中战斗、联机。
- 通用 Buff/Debuff 框架、复杂 Timeline、属性克制、完整技能树。
- 正式像素美术、特效、音效、剧情演出。

这些想法都可以保留在 `RPG设计.md`，但它们是第二阶段的设计库，不是当前的待办清单。

## 每次学习的固定节奏

一次建议只安排 60 到 90 分钟：

1. 用 10 分钟写清楚本次唯一目标，例如“攻击盒只在挥砍中段启用”。
2. 用 40 到 60 分钟实现和运行。
3. 用 10 分钟测试边界情况，例如连续按键、贴墙攻击、目标死亡后攻击。
4. 用 10 分钟记录完成项、未解决问题和下一次唯一目标。

如果某个阶段连续两次都卡住，不要继续堆功能。保存最小复现项目，先只解决一个报错或一个错误行为。

## 开始时的第一节课

第一节课只做阶段 1 的前半部分：创建 `Arena.tscn` 和 `LvBu.tscn`，配置四向移动输入，让一个临时吕布在屏幕上移动。完成后再开始状态机；不要在第一天创建魏延、行为树或技能。
