# War3 视角与 2D/3D 技术路线

日期：2026-10-02。

## 用户原话

> 如果要像是war3那种视角，是不是得做3d的游戏才行，就不能是2d的

## 结论

不必把玩法和角色都改成全 3D。Warcraft III 原作的世界、单位和相机是三维的，但“类似 War3 的斜俯视观察感”可以由多种组合实现：

1. 固定视角、平面战斗：纯 2D 或等距 2D 足够，但旋转镜头、真实高度和遮挡会受限。
2. 固定或轻微移动的斜俯视镜头：3D 场景 + 2D 角色最适合本项目当前 HD2D 方向。玩法仍可保持二维平面规则。
3. 自由旋转/缩放镜头、明显高低差、桥梁上下层、立体弹道：应逐步迁移为 3D 世界坐标、3D 碰撞和导航；角色仍可先用 Sprite3D / SubViewport 输出的 2D 骨骼人物。
4. 所有角色和场景都使用三维模型只是其中一种美术方案，不是实现 War3 视角的必要条件。

## 当前项目所处位置

当前 `HD2DArena` 已经使用 Camera3D、三维石台、墙柱、灯光、阴影和 Sprite3D 人物，视觉上属于 3D 场景承载 2D 角色。战斗规则仍以 CharacterBody2D / Area2D 运行，再把二维 XY 映射到三维 XZ。这很适合固定镜头、没有可行走高低差的演武场，同时能保留现有战斗代码。

如果后续目标只是“更像 War3 的镜头角度和空间感”，建议继续当前路线：增加透视相机、有限缩放、场景遮挡和地面高度视觉，不立即重写战斗物理。如果明确要求自由绕角色旋转镜头、单位走上坡/楼梯、穿过桥梁上下层或依赖三维弹道，再抽取移动/命中接口，将 CharacterBody2D、Area2D、NavigationAgent2D 分阶段替换为对应 3D 实现。

## 关键区分

- 画面维度：场景如何渲染。
- 角色资产：Sprite、二维骨骼还是三维模型。
- 玩法维度：位置、碰撞、导航和技能判定用二维还是三维坐标。
- 相机能力：固定、缩放、平移或自由旋转。

这四项可以独立组合。当前推荐继续“3D 场景 + 2D 骨骼角色 + 2D 平面战斗 + 固定斜俯视相机”，等真实关卡验证必须有高低差后再迁移玩法层。
