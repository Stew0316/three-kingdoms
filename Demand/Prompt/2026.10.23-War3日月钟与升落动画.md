# War3 日月钟与升落动画

## 用户要求

按用户附带的 War3 日夜时钟截图调整日月钟，让太阳和月亮随着时间慢慢移动；随后要求整体位置调高，继续完成。截图作为视觉参考，表框材质仍采用本项目的暗金属与铜饰表现。

## 实现

- 圆形天空盘中有薄云、夜空星点、太阳和月牙。日月沿同一弧线从左升起、经过顶部、向右落下，两者相差半个昼夜，边缘严格圆形裁切。
- 太阳/月牙、云层和星点全部读取全局时钟比例；无独立动画计时，暂停冻结，跨图延续。正式速度仍为每格五分钟、完整昼夜一小时。
- 金属表框保留十二枚镶点，整圈日间金黄、夜间蓝色，亮点连续交接。以本次截图方向替代旧外侧细光丝，保留弱柔光和天空内缘亮圈。
- 大小保持不变，装配位置由 `(260,9)` 改为 `(260,1)`，上移八个逻辑像素，即默认 1280×720 窗口中上移十六像素。
- 新增原生着色器 `Resources/Shaders/DayNightSky.gdshader`，不需要位图；既有 `DayNightHalo.gdshader` 保留但不再接入。

## 验证

- `dotnet build Three-Kingdoms.csproj --no-restore`：成功，零警告、零错误。
- Godot 4.7.1 .NET / D3D12 Forward+ / RTX 4080 Laptop：采集 96 帧完整昼夜及日夜全画面，检查太阳/月牙从左到右的轨迹、圆形边缘裁切、顶部位置和昼夜配色。未发现着色器编译错误。
- `--max-fps 60 -- --status-cycle-test`：59 项通过，含五分钟边界、十二格循环、暂停冻结、切图延续及现有底栏/改键/物品回归。日志 `Build/DayNightDialRegression60.log`。
- 首次不限帧运行在既有“新按键实际触发技能”检查失败；该检查在关闭菜单后按固定 70 帧等待，未保证动作恢复所需的真实时间。按 60 帧运行全部通过；本轮未改动该测试等待方式或战斗逻辑。原始日志保留为 `Build/DayNightDialRegression.log`。
- 沙箱运行提示不能写用户着色器缓存和不能读取系统根证书；仍成功进行 D3D12 实际渲染并正常完成测试。
