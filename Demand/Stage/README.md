# 吕布游历：项目阶段设计

版本：v0.3 · 2026-09-28 · 状态：S0 已验收，S1 可玩原型与自动回归已完成，正式人工试玩待验收。

## 游戏要做成什么

**固定操作吕布，在相连的城镇与野外游历，通过挑战、师承和探索收集技能，用有限的技能槽搭配打法，进行有刀光、光环和明确攻防节奏的 2D 实时战斗。**

“宝可梦感”落在路线探索、城镇补给、能力收集、有限携带、挑战后成长和重访旧区域；用户已明确：不收集可切换角色，不做武将编队。伙伴与名将仍可作为故事人物、传授者和对手。

用户已确认以 **单机 PvE** 为主，目前不做多人或 PvP。首发平台建议 Windows。网络系统不进入本路线；以后若需求变化，单独评估同步、权威判定和内容成本。

## 每个阶段交付什么

顺序为 `S0 → S1 → S2 → S3 → S4 → S5 → S6`；S7 不阻塞首发。Steam 商店准备可在 S4 后与 S5 并行。

| 阶段 | 可见产物 | 通过后才扩大的范围 | 初步有效工时 |
| --- | --- | --- | ---: |
| S0 | 当前版本基线、尺寸样板、运行与导出检查记录 | 固定开发约束 | 6–12 h |
| S1 | 吕布对魏延，可胜负、可重开 | 从木桩变成真实攻防 | 30–50 h |
| S2 | 同一入口驱动玩家和敌人，配置出不同技能 | 从两个技能到可扩展机制 | 45–75 h |
| S3 | 出城、学技能、训练、回营搭配、左慈两点传送、存读档 | 从竞技场到短冒险 | 50–90 h |
| S4 | 20–30 分钟精致切片及试玩反馈 | 验证玩法、美术、制作速度 | 60–100 h |
| S5 | 有开头结尾的首发候选内容 | 扩到一个中原小区域 | 120–200 h |
| S6 | Steam 测试通过的发布候选包及商店材料 | 首次商业发行 | 40–70 h |
| S7 | 按反馈确定的小更新或独立章节 | 一次一个内容包；不含联机 | 单独估算 |

工时是范围估计，不是交付承诺；包含阶段内实现与基本调试，未计外部审核等待、外包交期和大规模返工。S0–S6 合计约 351–597 小时，再预留约 30% 风险余量约为 456–776 小时。每周实际投入 15 小时约需 30–52 周。**只对眼前 S0/S1 排细任务，S4 后用真实产能重新估算后续。** 若美术返修超过估计，优先减地图、技能数量和演出，而不是压掉验证时间。

## 首发范围上限（提案，S4 后冻结）

| 项目 | 上限 |
| --- | --- |
| 玩家 | 固定吕布；一个核心武器动作体系，以戟术搭配术法 |
| 地图 | 一个中原区域：1 个起始村、2 个小城镇、4 个野外区块、2 个小洞窟；区块可复用地形套件 |
| 流程 | 首次体验约 2–3 小时，实际以试玩计时为准；一个完整篇章和结尾 |
| 敌人 | 4 类基础人形兵、3 场主要人形 Boss 战；不以换色计新增兵种 |
| 技能 | 8–12 个可装备主动技能、最多 3 个被动；普攻与闪避独立 |
| 携带 | 暂定 3 主动槽 + 1 被动槽；S1 仅实现 2 主动技能 |
| 任务 | 1 条主线 + 最多 3 条短支线；不做程序生成任务和无限刷取 |
| 成长 | 少量等级提升、技能有限强化、固定装备；不做随机词缀海量刷装 |
| 旅行便利与训练 | 左慈连接已到访并激活的城池，安全歇脚点可归驿；最多 3 课，共享收益额度，连续 100 分钟不锻炼恢复，并有章节成长上限 |
| 坐骑与三仙 | 1 匹普通马，赤兔候选、总上限 2 匹；南华引导训练、左慈负责传送、于吉短支线；不做马战与养宠日常 |
| 语言 | 默认简中；繁中、日语、英文为目标语言，发布声明以实际完整校对结果为准 |
| 平台 | 首发 Windows；手柄支持；其他系统、Steam Deck 和联机单独实测评估 |

技能收集比角色收集省下多套玩家动画，但每个新技能仍有动作、命中、反馈、敌人适配、本地化和平衡成本。新技能优先组合已有机制；一个新技能最多引入一个未经验证的底层机制。

## 阶段执行规则

1. 当前主目标只有一个：交付本阶段可运行版本。按需学习，不再以学完行为树、着色器等知识章节作为进度。
2. 每个阶段留下版本号、导出包、短录屏、验收记录、遗留问题。未做验证的项目保持未勾选。
3. 严重问题必须先处理：无法进入流程、无法通关、崩溃、损坏存档、核心判定错误。装饰效果可以延期。
4. 连续两轮试玩仍无法体现阶段核心乐趣，先减系统或调整规则；不靠多加地图与特效补救。
5. 原 [学习路线](../Line/学习路线.md) 作为按需查阅资料。其独立目录建议不再照搬，继续沿用项目 `Scene / Scripts / Source / Components / addons`。
6. `Demand/Stage` 是本次设计产物目录，沿用仓库现有 `Demand` 大小写。没有新建根目录，也没有改动现有游戏实现；本文中的规划目录与接口不代表已创建。

[S0](S0-基准与范围冻结.md) 已于 2026-09-28 验收。[S1 原型](S1-实现与验证记录.md) 已接入写实武将 PNG、共用战斗能力、AI、血条、胜负与重开；下一步是人工试玩与手感调优，完整 S1 验收前不进入 S2。
