这些是继续迭代的基础，无需重建整个项目。

## 执行任务

1. 用当前工具链启动现有入口，记录能运行的内容、报错、Godot/.NET/模板版本和机器配置。创建开发基线，不在同一轮顺手升级引擎。
2. 固定 S1 输入动作：移动、普攻、技能 1、技能 2、闪避、暂停、重开；全部通过 Input Map，后续可以改键和适配手柄。测试恢复血量单独标记为开发动作。
3. 固定“移动碰撞、攻击判定、受击判定、交互触发”的物理层职责。现有 `layer_names/2d_render` 是渲染层命名，不能充当物理碰撞层配置。
4. 按 [风格规范](风格-美术与特效规范.md) 做一个角色静态样板、一个地块和一个刀光草样，用来验证尺度与可读性。正式动画在 S4 制作；S1 可以继续用占位图。
5. 暂定 640×360 世界视口、32px 瓦片、64px 角色帧，HUD 单独排版。现有角色/碰撞体较大：验证一间房的比例后统一调整测试场地，不机械保留旧速度、距离数值。
6. 固定 Windows 桌面为首个验证目标，导出一次最小包并从编辑器外启动。记录全部依赖文件，避免只复制 exe。
7. 新界面文案以稳定翻译键命名，例如 `UI_BATTLE_RETRY`；现在只填简中。内容 ID 如 `core.skill.crescent_sweep` 不随语言和显示名改变。

## 目录约定（未来按需创建）

| 路径 | 职责 |
| --- | --- |
| `Scripts/Combat`、`Scripts/Characters`、`Scripts/AI` | 战斗、角色与决策实现 |
| `Scripts/Config` | 本游戏的配置与内容定义，优先使用现有结构 |
| `Scripts/World`、`Scripts/Progression`、`Scripts/Save`、`Scripts/Platform` | S3/S6 才逐步引入 |
| `Scene` / `Components` | 完整场景 / 可复用角色、HUD、交互和特效场景 |
| `Source/People`、`Source/City`、`Source/Terrain` | 角色、城池、地形资源，保留已有分类 |
| `Source/Effects`、`Source/UI`、`Source/Audio`、`Source/Localization` | 到对应阶段真正有文件时再创建 |
| `addons` / `BaseSource` | 只有跨项目通用代码进插件目录；工作室公共资产进 BaseSource |

不为每个接口建立空插件。S0 已新增 `Source/StyleGuide`，并按 AGENTS.md 同步资源目录说明。
