## 本次固定的开发约定

### 输入

| 动作 | 键鼠 | 手柄起点 |
| --- | --- | --- |
| 移动 | 方向键 / WASD | 沿用 Input Map 后续补左摇杆 |
| 普攻 | J / 鼠标左键 | X |
| 技能 1 | K | Y |
| 技能 2 | L | B |
| 闪避 | Space | A |
| 暂停 | Esc | Start |
| 重开 | R | 暂未绑定 |
| 开发回血 | H | 仅保留为开发动作，不进入正式控制说明 |

S1 的代码只读取动作名，不直接读取键值。手柄摇杆与重开键在 S1 做控制器实机验证时补齐。

### 物理层

| 层 | 名称 | 责任 |
| ---: | --- | --- |
| 1 | `world_body` | 地形与现有实体根碰撞；S1 组件化时拆分实体身体层 |
| 2 | `player_hurtbox` | 玩家受击区域 |
| 3 | `player_body` | 玩家移动实体 |
| 4 | `enemy_hurtbox` | 敌人受击区域 |
| 5 | `enemy_body` | 敌人移动实体 |
| 6 | `interaction` | NPC、传送点、宝箱等触发区域 |
| 7 | `projectile` | 投射物与远程判定 |

现有玩家和木桩根节点仍使用旧的 layer 1；S1 第一步组件化时迁移到 3/5，并保留与世界碰撞的 mask。当前玩家攻击检测 layer 4、敌方攻击检测 layer 2，与新命名一致。

## 导出缺陷与修复

第一次 Release 导出暴露了 `addons/uid_assigner/UidAssignerPlugin.cs` 在运行时发布中引用 `EditorPlugin` 的问题。`addons` 是独立仓库，因此主项目在非 Debug 配置中排除该编辑器专用脚本，不修改插件仓库；修复后 `.NET publish` 通过。

导出预设排除了 `Build/**`，避免把本地构建产物再次塞进 PCK。`.gitignore` 同步忽略 `Build/`。

## 已知缺口

- `Scene/base.tscn` 仍是木桩测试入口，`Scene/Arena.tscn` 主要提供边界，尚不是完整对战场。
- 玩家与木桩根碰撞仍共用旧层；角色组件、生命绑定、死亡清理和攻击命中去重留给 S1。
- 当前角色、地块和碰撞尺度来自旧原型，S1 搭一间 640×360 测试房后统一标定。
- 两条 RGB8 纹理在 D3D12 启动时被运行时转换为 RGBA8，不阻塞 S0；正式资源导入时统一格式，避免运行时转换。
- 目前没有录屏和手柄实机记录；这两项在需要完整玩 10 局的 S1 验收中完成。

## S1 开工顺序与范围边界

1. 将玩家和敌人整理成可复用组件，接通双方 Health/Hurtbox 和物理层。
2. 修正普攻状态、固定施放方向、每次攻击命中去重与取消清理。
3. 加受击、击退、死亡和血条。
4. 用简单状态决策实现魏延的追击、预警、攻击与后摇。
5. 实现突进、横扫、闪避、冷却显示和范围提示。
6. 加胜负、重开并在独立包完成至少 10 局验证。

S1 不做世界地图、技能收集、训练、坐骑、左慈传送、剧情量产、多人或 PvP，也不先写通用行为树插件。阶段目标只有“吕布对魏延的一场完整实时 PvE 对战”。
