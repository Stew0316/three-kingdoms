# S1：吕布对魏延，一场可反复玩的实时对战

2026-09-28 实现进度：可玩原型已完成，见 [实现与验证记录](S1-实现与验证记录.md)。本轮按用户最新要求使用写实比例单张 PNG；正式四朝向动画与人工试玩验收仍未完成，下方总体验收清单保持未勾选。

前置：S0 基线完成。预算 30–50 有效小时。阶段问题：**只给一间场地和两种技能，攻击、闪避、找破绽是否已经有趣？**

## 玩家看到的成品

进入测试场 → 吕布与魏延出现 → 魏延追击和释放有预警的招式 → 吕布普攻、突进、横扫和闪避 → 一方死亡 → 胜负面板 → 一键重开。

保留占位美术，但必须有短促命中反馈、清楚的攻击范围和可感知的前后摇。当前阶段不引入世界地图、掉落、技能收集或正式剧情。

## 最小规则（调参起点）

| 项目 | 规则 |
| --- | --- |
| 移动与朝向 | 平面八方向移动；四朝向画面起步；普通近战施放时记录方向，不受随后转向影响 |
| 普攻 | 前摇 → 生效窗口 → 后摇；每个目标每次挥击最多受伤一次 |
| 技能 1：突进 | 向施放方向快速位移，碰墙停止；第一版不带无敌，不穿墙 |
| 技能 2：横扫 | 大于普攻的扇形范围，代价是较长前摇和冷却 |
| 闪避 | 独立于可收集技能；短位移、独立冷却；第一版仅用于走位，不带无敌帧 |
| 状态 | Idle / Move / Attack / Dodge / Hurt / Dead；死亡最高优先级，禁止继续施法 |
| 受击 | 扣血、短硬直、受约束的击退、短闪白；命中停顿先仅影响交战角色 |
| 资源 | S1 技能仅用冷却约束；体力/真气留待实测，暂不同时加入两套资源条 |
| AI | 发现 → 接近 → 预备攻击 → 生效 → 后摇；距离不对或冷却中重新走位 |

初始数值仅供可视化调试：吕布 HP 120、魏延 HP 100；普攻伤害 12/10；普攻前摇约 0.15–0.25s，生效约 0.10s，后摇约 0.20s；突进 CD 3s、横扫 CD 5s、闪避 CD 1.2s。距离和速度先按 S0 的角色尺度标定；后续每次只改一个影响手感的变量。

## 开发顺序与完成证据

| 顺序 | 要完成的工作 | 当次可演示结果 |
| --- | --- | --- |
| 1 | 将角色做成可复用组件场景；吕布和魏延都接 Health/Hurtbox | 双方能受伤并正确死亡 |
| 2 | 修正现有攻击：进入 Attack 状态、固定施放朝向、命中去重、结束清理 | 连续按键也不重复结算；离场后无延迟命中 |
| 3 | 加受击、击退、死亡处理与血条 | 被打后有反应，血量和状态一致 |
| 4 | 建立魏延最小追击/攻击决策；通过与玩家相同的施法入口 | 魏延会主动接近、预警、出手和留破绽 |
| 5 | 做突进、横扫、闪避；加入范围预览与冷却显示 | 能主动躲开一次攻击，并趁后摇反打 |
| 6 | 整合胜负与重开，导出并完整玩数轮 | 一局闭环不依赖编辑器或调试按键 |

第一次实现继续复用 `DamageInfo / Health / Hurtbox`，不用提前把全部 Buff 框架做完。`LB.PerformAttackAsync()` 的延迟必须受本次施法有效性约束；死亡、重开、节点离树后不能继续启用旧 Hitbox。详细迁移见 [架构附录](附录-战斗与扩展架构.md)。

AI 先用简单状态决策即可。本阶段不把“写出行为树插件”当验收要求；S2 复杂到需要组合时再改，行为一致性比实现形式重要。

## 验收场景

- [ ] 能完整进行至少 10 局，覆盖玩家胜利、玩家失败、重开；没有残留敌人、信号或计时回调。
- [ ] 一次挥击多帧重叠、退出后再次进入、目标有多个受击区域，仍只按预定次数扣血。
- [ ] 攻击中转向、连点、受击、死亡、暂停和退出场景，不会出现延迟攻击或永久锁状态。
- [ ] 玩家与 AI 的伤害和冷却走同一规则；AI 不跳过前摇、沉默等未来权限入口。
- [ ] 贴墙突进/击退不穿墙；死亡单位不再移动、施法和结算新命中。
- [ ] 能看清敌人何时要攻击、何时可以反打；至少 2 名试玩者不靠口头提示完成一局。
- [ ] 整局导出可运行，留下约 1 分钟录屏和数值调整记录。

上述次数用于发现重复运行问题，并不代表完整质量保证；出现不稳定错误应保留复现步骤。

## 控制规模

若时间超出预算上限，先减少动作帧和 AI 招式变化，仍保留普攻、两技能、闪避、受击、胜负闭环。若躲避窗口太短或普攻明显没有用途，继续调节 S1，不进入 S2 堆技能。
