# S2：用少量机制支撑有变化的技能

前置：S1 可反复完成。预算 45–75 有效小时。目标：给吕布和敌人共用一套技能执行规则，让增加技能主要成为配置、表现和少量新效果的工作。

## 玩家可见变化

测试场增加方向防御、牵引后延迟攻击、短时光环或受控反伤等变化。玩家开始需要判断距离、角度与施放时机，不能只站桩互扣血。最多验证 4–5 个主动技能定义，仍然没有大量地图内容。

## 必要模块

| 模块 | 本阶段做到什么 | 先不做什么 |
| --- | --- | --- |
| 技能定义 | 稳定 ID、翻译键、目标方式、前后摇、冷却、效果列表、表现引用 | 自制可视化技能编辑器、任意运行时脚本 |
| 施法实例 | 每次 Cast 的来源、方向快照、目标、已命中集合、取消标记 | 把 CD 或已命中集合写进共享 Resource |
| Timeline | 以相对时间触发开启命中、投射物或效果事件；允许取消 | 全局过场/剧情/网络回放都塞进同一调度器 |
| 伤害结算 | 有来源可追踪；物理/术法分量；方向判定；护盾/减伤；结果事件 | S1 就实现所有元素抗性、任意优先级脚本 |
| Buff | 加入、刷新/叠层、Tick、移除；受击/施法等明确事件；移动/施法权限 | 用 Buff 保存长期任务和世界进度 |
| 表现层 | 响应已提交的施放、命中、死亡事件，播放动画音效与特效 | 让粒子碰撞或动画显示帧数决定伤害 |
| AI | 调用同一命令与技能可用性查询，优先表现可理解的战术 | 对玩家隐藏冷却作弊或每帧随机换招 |

完整契约、数据流和示例技能见 [战斗与扩展架构](附录-战斗与扩展架构.md)。不要求把附录的后期可选部分一次实现。

## 机制验证顺序

1. 用新定义重建 S1 的突进和横扫，保持手感，证明重构等价。
2. 加一个方向防御：正面减伤，背后可以突破；确认入射方向是命中快照而非延迟读取。
3. 加一次“牵引 → 清楚的蓄力提示 → 范围斩”：牵引不伤害，随后留出可闪避窗口，验证控制、时序与取消。
4. 用光环验证范围内增益、离开失效、来源死亡清理；不让角色脚下光环与危险预警混淆。
5. 最后用小型测试配置验证反伤不会无限互相触发，不因一次 Hitbox 多回调重复结算。

这些验证配置不必全成为首发可收集技能。原始设计中的多重施法、偷技能和变身先只保留设计扩展点；实际加入要在 S7 独立验证。

## 本阶段开始的约束

- `SkillDefinition` 等静态定义只读，角色技能等级、冷却、Buff 层数和施法临时状态互相分开。
- 先采用一个明确的 CD 提交策略，详见架构附录；失败施法不进入 CD，已承诺的施法被打断按规则结算，不可通过取消白嫖伤害。
- 战斗时间、角色动作速度、短命中停顿和界面时间分开。菜单动画、重开按钮不能随命中停顿冻结。
- 所有内容都有 ID 和包归属 `core`；此时只是数据字段与注册表，不是开始开发 DLC 商店。
- C# 枚举适合有限的规则类别；不断增长的技能、任务、物品使用稳定内容 ID，不能按显示名查找。

## 验收与交付

- [ ] 至少两个技能通过修改定义组合出来，不复制一份角色攻击脚本。
- [ ] 两个敌人使用同一技能资源，互相不共享 CD、目标或命中列表。
- [ ] 正/侧/背面命中、无攻击者的环境伤害、两种伤害分量、目标已死都得到明确结果。
- [ ] 两个反伤单位互打时事件链有限；一次死亡只发一次死亡奖励事件。
- [ ] Buff 刷新、叠层、到期、驱散、来源死亡与清图均有确定行为；硬控不能被重复叠加永久锁死 Boss。
- [ ] AI 与玩家在相同沉默、硬直、冷却条件下都不能非法施法。
- [ ] 暂停、加速、命中停顿后 Timeline 不丢事件、不重复触发，恢复后 UI 正常。
- [ ] 留下技能定义样例、伤害事件记录和一页规则说明，S1 的胜负闭环仍可运行。

对伤害顺序、叠加、反伤链这类高风险规则写少量针对性单元测试；时序、碰撞和效果清理仍必须在场景中验证。不为每个数据字段写重复测试。
