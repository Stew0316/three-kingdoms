# 锻炼收益：连续休息 100 分钟后恢复

更新：2026-09-28。用户已要求用实际时间限制收益：连续 100 分钟不锻炼后，继续锻炼才重新有收益。本文件替代早稿“每课永久只奖励一次”的规则，是训练收益的权威说明。

## 玩家规则

**一次收益机会 → 成功锻炼消耗机会 → 连续 100 分钟未锻炼 → 恢复一次机会。** 再加章节累计成长上限，控制该内容阶段的最大强度。

| 项目 | 规则 |
| --- | --- |
| 时间依据 | 现实经过时间，不用游戏昼夜或加速后的战斗时间；暂停、在别处游历和退出游戏均计入休息 |
| 恢复条件 | 从最后一次实际锻炼活动结束起，连续满 100 分钟（6000 秒）未锻炼 |
| 每轮额度 | 暂定 1 次有收益的成功训练；首次解锁训练时先给 1 次，不要求先等 100 分钟 |
| 额度上限 | 最多储存 1 次；离线很久不会按每 100 分钟累积大量次数 |
| 课程关系 | 已解锁的任意课程共用同一额度和休息计时；换课程、换训练场、换城不能绕过 |
| 无额度时 | 仍可复练动作，但不增加永久属性；实际复练也算锻炼，会重新开始 100 分钟休息计时 |
| 失败/取消 | 不消耗尚未用掉的收益机会；但发生了锻炼，记录活动结束时间，不能算作休息 |
| 只浏览界面 | 看课程说明、查看倒计时不算锻炼，不重置计时 |
| 再次获得收益 | 休息后可以重练同一课取得下一次成长，不要求必须换课 |
| 当前章节上限 | 暂定 3 次有收益训练；每次增加初始基准 HP 的 2%，合计不超过 6%，不复利；这是可调提案 |
| 达到章节上限 | 仍可复练，但休息不会绕过成长上限；明确显示“本阶段成长已达上限” |

本体先按一个篇章、3 次总成长预算设计；未来新篇章若新增训练预算，在配置中明确增加，不能因重复进入章节而重置已领取次数。课程通过、最高成绩与属性收益是不同数据。完成三课的成就只看课程通过，不要求等待三轮收益。

100 分钟限制控制成长速度，章节上限控制最终强度；只有计时没有累计上限，长期重复依然可能超出内容。训练始终是可选容错增益，不把主线必需技能、左慈传送或坐骑锁在计时等待后。

## 时间示例

| 行为 | 结果 |
| --- | --- |
| 12:00 完成第一次有收益训练 | 额度变 0，若没有继续锻炼，13:40 恢复 1 次 |
| 12:30 只打开课程面板 | 仍在 13:40 恢复，不重置 |
| 12:30–12:31 无收益复练 | 从 12:31 重新休息，到 14:11 才恢复 |
| 12:00 训练后退出，14:00 再启动 | 已满 100 分钟，恢复 1 次；不累积多次 |
| 13:39 开始无收益练习，13:41 才结束 | 入场时无额度，本次无收益；到 15:21 才恢复，不能在训练中跨过阈值领奖 |
| 带着 1 次额度训练失败 | 不扣额度，允许立即重试；不会因为失败强迫再等 100 分钟 |
| 本章已经获得 3 次成长，隔天再来 | 仍到达本章上限，只有练习反馈 |

以上按完整 100 分钟作为恢复边界；不是每天零点刷新，也不是“在线玩够 100 分钟”。若今后改为只累计在线时间，属于规则变更，需同步存档版本与说明。

## 界面与南华提示

训练面板显示“本轮收益机会 0/1”“本章成长 1/3”“连续休息剩余 37:20”。有额度时显示“本次达标可获得成长”；无额度时进入按钮写“仅练习”，附说明“开始练习会重新计算休息时间”。不增加多层确认框。

南华/导师可用“修行亦需消化，出去游历一番再来”解释机制，但倒计时与上限直接写清楚，不用剧情隐去规则。章节上限已满时优先显示上限原因，不能只显示倒计时让玩家误以为等完还有收益。

## 数据和结算设计

```text
TrainingProgress
  schemaVersion
  rewardCredit                 // 0 或 1
  lastTrainingActivityUtc      // 最近实际训练活动时间，UTC
  lastObservedUtc              // 时间回拨检查基准
  rewardedSessionIds          // 防重复提交
  chapterRewardCounts         // 各章节已获得成长次数
  completedCourseIds          // 课程通过，与收益分开
  activeSession               // 临时：会话ID、入场可得收益标记
```

训练面板/入场时先刷新资格：没有活动中的训练，额度为 0，距离最后活动满 6000 秒，才恢复到 1；不累计多个周期。随后检查章节上限。入场时锁定本次是否有收益，避免在一场持续训练中“等够时间”转换资格。

开始、完成或取消训练时记录时间；活动中的训练周期性记录最近活动时间，退出时结算结束时间。异常退出重进后按未完成训练处理，不发奖励，并以最近持久化的实际活动时间计算休息；这个周期的误差要有界，建议不超过 10 秒。

成功结算时将会话 ID、永久增量记录、章节计数与额度消耗作为同一次存档提交。相同会话不能重发；不直接在回调里无条件 `最大生命 += 奖励`。数值由有效收益记录重建。HP 若用整数，按固定初始基准向下取整每次加值，保证不突破上限。

现实计时独立于技能 CD、暂停、慢动作和 `TimeScale`。同一运行会话用不受游戏速度影响的计时核对经过时间，跨启动用 UTC 记录；本机时间回拨时不提前恢复额度，提示时钟异常并保留档案。单机离线无法可靠防止玩家主动修改系统时间，不为此增加服务器或强制联网。

旧档迁移：如早期原型已有一次性课程奖励，将其映射为已消耗的章节成长次数，保留既有属性；不能迁移后再送同额增量。S6 云同步沿用完整存档冲突选择，不把两台设备的训练奖励直接相加。

## 阶段与验收

- S3：一门课程、共享额度、100 分钟现实计时、章节上限、提示与存读档全部接通。
- S4：试玩验证玩家不会误解规则；20–30 分钟切片只需展示首次收益和下一次条件，不要求试玩者等满 100 分钟。
- S5：最多三课，共用同一收益状态；全语言说明与南华提示一致。
- S6：离线再启动、云档切换、旧档迁移与系统时间异常回归。

验收必须覆盖 99:59 / 100:00 边界、离线恢复、无收益复练重置、失败保留额度、换课不绕过、章节上限、重复结算和回拨时钟。开发测试通过可注入时间源快进，不真实等待 100 分钟，也不把开发跳过计时入口留在发布包。

这是按用户需求制定的本作规则；未将“100 分钟”声称为已核实的《魔女之泉》原版精确数值。
