# 战斗、技能收集与后续扩展架构

> 设计日期：2026-09-28。此文件是阶段设计的技术附录，不是已经完成的系统说明，也不要求一次实现全部结构。项目以 Godot 4.7.1 C# 为目标；本文先安排 S1 可玩战斗，再安排 S2 抽取内核。数值均为首轮试玩起点。

## 1. 需求记录与本次设计边界

用户本次请求：**“帮我完成这个阶段设计，设计出来的产物，放入到/demand/stage下”**。

相关原始问题来自 [2026.9.28.md](../Prompt/2026.9.28.md)：

> 我的对战形式是实时对战，我希望技能风格可以像是dota2那种有想象力的，然后可以扩展性好一些的，而且我希望可以尽量实现Design里的RPG设计。

> 酷炫效果的话，我希望可以参考起凡群雄逐鹿的刀光，还有脚下的光环，还有dota1的光环，然后后期也会考虑dlc，我希望也有一些是dlc的预埋逻辑。

本轮补充确认：**主角固定吕布，主要收集技能，不切换角色**。因此，“宝可梦版三国”在这里落实为游历、挑战、收集招式、选择搭配与成长；伙伴先承担 NPC 和剧情职责，不做可切换武将、队伍 AI 或召唤伙伴战斗系统。

建议战斗中携带 **3 个主动技能 + 1 个被动技能**，普攻、闪避单独占操作入口。槽位数是设计提案，可通过切片试玩调整，不是已经确认的硬性需求。用户已确认主要做 **单机 PvE，目前不考虑多人或 PvP**；网络功能不在本轮排期。

采用 [RPG设计](../Design/RPG设计.md) 中的命令、技能时间线、伤害流转、Buff 权限、方向减伤和技能习得思路，同时作三项收敛：

- 首期使用少量固定效果组合和少数专用效果类，不造通用可视化技能编辑器。
- 任务进度属于独立任务系统，不挂在 Buff 中；两者可以订阅同一条击败事件。
- 首期不做任意偷取最后一个技能、完整变身复制 Boss、多重施法随机递归。击败或完成挑战后，解锁预先设计并验证过的“玩家版招式”。

## 2. 当前代码能保留什么，先修什么

已阅读 `Scripts/LB.cs`、`Scripts/Combat/DamageInfo.cs`、`Health.cs`、`Hurtbox.cs`。`Three-Kingdoms.csproj` 声明 `Godot.NET.Sdk/4.7.1`，`project.godot` 声明 4.7、C#、Forward Plus；这些是仓库配置证据，不等于已经验证本机安装与导出。

| 现有结构 | 可保留部分 | S1 必须补足的行为 |
| --- | --- | --- |
| `LB : CharacterBody2D` | 移动、四方向朝向、角色场景连接点 | 攻击实际进入 Attack；死亡拒绝输入；命中受击能中止当前攻击；攻击朝向按规则锁定 |
| `PerformAttackAsync` 三段延迟 | 0.12 秒前摇、0.10 秒判定、0.13 秒后摇可作为第一版手感基准 | 死亡、受控、退出场景后禁止旧等待恢复攻击；推荐改成逐物理帧推进的明确阶段计时 |
| `AttackHitbox.AreaEntered` | 发现重叠对象的入口 | 阵营筛选、目标有效性、每次攻击去重；处理判定打开时已经重叠的目标 |
| `DamageInfo(Attacker, Amount, KnockbackDirection)` | “统一提交伤害”的方向 | S1 加来源身份与攻击实例；S2 演进为伤害请求与结算结果，不让各处直接修改生命 |
| `Health` | 当前生命、最大生命、死亡/伤害信号 | 拒绝负伤害；治疗独立入口；死亡只结算一次；重开同步 UI，不把重置和复活混为一谈 |
| `Hurtbox` | 命中体与生命组件分离 | 缓存或显式绑定接收者，不在每次命中按节点名查找；转交统一结算器 |

现在 `LB` 的攻击未调用 `SetState(Attack)`，攻击中仍会按方向输入更新 `Facing`；攻击框在开始时定位，伤害方向在碰撞时读取当前朝向，二者可能不一致。S1 先处理这个可观察问题，再谈完整技能框架。

### 2.1 迁移顺序：每一步保持可玩

1. **S1 前半：修好现有普攻。** 保留 `LB` 和场景，把一刀明确分成前摇、有效、后摇；引入本次攻击编号、已命中集合、死亡与退出取消。先允许少量代码直写时长。
2. **S1 后半：做出吕布与魏延单场。** 吕布普攻、独立闪避，以及分开的突进、横扫两个主动招式；魏延使用相同伤害接收入口。角色状态改变必须同步关闭旧判定。牵引接蓄力留到 S2。
3. **S2：有重复再抽取。** 从两个技能抽出 `SkillRunner`、`SkillDefinition` 和 `SkillCast`；从双方受击抽出 `DamageResolver`；加入少量 Buff 和权限聚合。
4. **S3：加入技能收集与持久化。** 解锁技能、营地配装、技能成长、任务、存档。NPC 和玩家输入只是命令来源不同。
5. **S4 之后：按瓶颈优化。** 只在测出频繁分配或大量粒子压力后加池化；只在实际出现重复需求后提取通用插件。

S1 不要求事件总线、依赖注入容器、ECS、节点编辑器、任意脚本热加载、网络回滚或自动存档迁移框架。S2 的大多数业务对象可以是普通 C# 类型，场景节点负责物理、动画、音效和生命周期。

## 3. 定义、单位状态、每次施法必须分开

Godot 的资源加载存在缓存，同一路径可能返回共享资源引用。因此，“技能配置里存 CD 剩余时间”会让多个单位或技能实例互相污染。`resource_local_to_scene` 有适用场景，但不能代替明确的数据所有权设计。[Godot Resource 官方文档](https://docs.godotengine.org/en/stable/classes/class_resource.html)

| 层 | 建议形态 | 存什么 | 不存什么 |
| --- | --- | --- | --- |
| `SkillDefinition` | 自定义 `Resource` / `.tres`；运行中只读 | 稳定 ID、文本键、消耗、CD、目标规则、时间线、效果参数、玩家/Boss 变体关联 | 当前等级、CD 剩余、命中集合、释放者节点 |
| `BuffDefinition` | 只读配置 | 持续、叠加、驱散类型、权限、数值修正、效果显示键 | 当前层数、剩余时长、来源实例 |
| `UnitRuntime` | 每个单位独立 C# 状态 | 生命、资源、属性、阵营、已学技能与等级、逐技能 CD、Buff 容器 | 对共享 Definition 的运行时修改 |
| `SkillCast` | 每次施法新建实例 | CastId、释放者、阶段时间、资源预留、朝向快照、HitGroup 集合、取消原因 | 跨多次施法复用的可变状态 |
| `BuffInstance` | 每次有效挂载独立实例 | 来源、目标、层数、剩余时间、Tick 游标、派生订阅 | 改写原始 BuffDefinition |
| `EffectInstance` | 区域/投射物的场景实例及运行状态 | OwnerUnitId、CastId、寿命、命中策略、归属房间 | 用节点路径充当永久存档 ID |
| 存档 DTO | 可序列化普通数据 | 技能 ID、等级、强化选择、存档版本、地图 ID、任务状态 | Godot 节点、Delegate、运行中的 Task、碰撞体 |

“只读”是项目约定，需要代码约束：编辑器中的配置仍可编辑；进入战斗后只读取，等级计算返回新数值，不执行 `definition.Damage += ...`。材质颜色、命中闪白等角色独有表现参数，也不能误改所有角色共享的材质资源。

配置第一版只提供实际需要的效果种类：位移、伤害判定、施加/移除 Buff、创建区域、表现提示。非常特殊的能力允许写一个小的专用效果类，不为了一个技能扩展出几十种泛型组合器。

## 4. 一次操作经过哪些层

```mermaid
flowchart LR
    I[玩家输入或敌人 AI] --> C[角色命令]
    C --> G[状态与权限检查]
    G --> S[技能实例与时间线]
    S --> H[位移与命中收集]
    H --> D[伤害结算]
    B[Buff 修正与触发] --> G
    B --> D
    D --> R[生命与状态结果]
    R --> E[表现事件]
    E --> V[动画 刀光 粒子 音效 UI]
    R --> Q[任务与成长事件]
```

### 4.1 命令与状态

命令先限制为 `Move`、`BasicAttack`、`Dodge`、`CastSkill`、`CancelCast`、`Interact`。输入层只表达意图，不能直接扣血、搬动目标或强行改变技能状态。敌人 AI 使用相同 `TryExecuteCommand` / `TryCast` 入口，不能绕过 CD、沉默、死亡等检查；Boss 豁免来自显式配置。

不要把每种 Buff 都变成状态机状态。基础行动状态保留 `Idle / Move / Attack / Cast / Dodge / Hurt / Dead`；眩晕、沉默、定身等提供权限约束。状态优先级先定义为：死亡 > 强制控制/中断 > 当前不可取消阶段 > 普通命令。受击是否造成中断，由命中结果与目标抗打断规则决定，不是每次扣血都强制进入 Hurt。

S1 暂不做复杂指令缓存。若手感需要，S2 最多允许一个短时普攻/闪避缓存，过期丢弃；死亡、换图清空缓存，防止复活后自动挥刀。

### 4.2 技能时间线

一条时间线按有序节点推进：**校验 → 前摇 → 提交释放 → 有效窗口/持续阶段 → 后摇 → 完成**。同一帧跨过多个节点时按顺序执行，每个节点至多一次；有效判定的开启和关闭有明确编号，不能依赖“碰巧刚好等于某个时间”。

S1 用角色内的简单阶段计时即可；S2 才抽取通用 `SkillRunner`。`AnimationPlayer` 根据技能阶段播放动画、刀光和音效；伤害是否发生由战斗时间线裁定，避免更换动画素材或丢帧后多打/漏打。动画时长改变后要检查判定帧，不能让明显的刀光早于实际伤害数百毫秒。

### 4.3 消耗与 CD 的提交时点

默认规则：**进入前摇时预留资源，提交释放时一次性扣资源并开启 CD**。

| 时点或取消原因 | 资源 | CD | 对玩家的含义 |
| --- | --- | --- | --- |
| 检查失败 | 不预留、不扣除 | 不变化 | 返回“资源不足/被沉默/目标无效”等原因 |
| 前摇开始 | 预留，其他操作不能重复花用 | 尚未开始 | 只展示准备态 |
| 主动取消前摇 | 释放预留 | 0.2 秒取消恢复期，技能完整 CD 不开 | 可取消，但不能无成本每帧骗 AI |
| 提交前受控/死亡/换图 | 释放预留 | 完整 CD 不开 | 没有实际放出的技能不扣完整成本 |
| 提交释放 | 扣预留资源，恰好一次 | 从提交时刻开始 | 即使随后打空也已付费 |
| 提交后被中断或主动取消 | 默认不退款 | 正常继续 | 不通过闪避取消刷新技能 |

提交前重新校验资源所有权、目标和距离；若技能允许对空释放，则不需要“仍有目标”。持续消耗型技能暂不进 S1；需要时由明确的每次 Tick 事务支付，资源不足立即结束，不能用负资源抵扣。

0 消耗技能仍有自己的 CD。CD 归属于单位的 `SkillId`，不归属于快捷栏槽位。换槽、卸下再装备、重载地图，都不能重新获得一次免费施法。

## 5. 取消、死亡、换图和时间域

### 5.1 每个技能都要有清理合同

终止原因至少区分 `Completed / PlayerCanceled / Interrupted / OwnerDied / SceneChanged`。终止操作可以重复调用，结果一致：关闭判定、释放未提交预留、恢复移动权限、停止跟随特效、解除订阅、结束动画占用、清空待处理目标。清理只撤销本次 CastId 拥有的判定、权限和订阅，旧技能的清理不能关闭新技能的判定或把仍受其他控制的角色设为可移动。清理不能依赖动画“最后一帧一定会播放”。

S1 若暂时保留异步等待，每次恢复后必须检查释放者有效性、当前 CastId 和取消代次；单有 `CancellationToken` 而没有把等待和清理接进去，不算实现取消。更简单的方案是把这三个等待改为物理帧阶段推进，让场景退出直接销毁运行状态。

持续效果明确写所属策略：

| 效果 | 默认归属和结束方式 |
| --- | --- |
| 贴身刀光、引导光环、蓄力 | 归本次施法；取消、死亡、换图立即终止 |
| 已经射出的独立飞镖 | 归房间；施法者死亡可继续到寿命结束，伤害来源 ID 仍保留 |
| 插地旗阵 | 归房间中的施法者效果；本方案默认死亡、换图时消失；同一技能最多一个 |
| 中毒/燃烧 | 归目标 Buff；来源死亡后可按已记录来源继续；目标死亡或换图按 Buff 策略清除 |
| 纯装饰残影 | 不再具有伤害权；短时间淡出，不能反向影响技能是否结束 |

首期换图前必须脱离战斗，销毁旧房间战斗效果，不跨地图保留飞镖、命中窗口、旗阵和追踪目标。死亡重试重置整场遭遇，避免只复活吕布却留下前一轮 Boss 技能。

### 5.2 三种时间，不用一次全局停时解决所有问题

| 时间域 | 推进内容 | 暂停菜单 | 打击停顿 | 动作加速 |
| --- | --- | --- | --- | --- |
| 实际时间/UI 时间 | 菜单、输入导航、提示淡入、停顿结束计时 | 继续 | 继续 | 不受影响 |
| 战斗时间 | CD、资源恢复、Buff 持续与 Tick、房间效果寿命 | 停止 | 默认继续 | 不受影响 |
| 单位动作时间 | 攻击前后摇、局部动画、攻击位移 | 停止 | 参与停顿的单位停止 | 按动作倍率推进 |

S1 优先做攻击者与受击者的短局部停顿，建议从 30–50 毫秒试起，并设连续停顿上限。UI、退出菜单和停顿恢复计时不走被冻结的时钟。单位动作倍率不自动缩短 CD 或眩晕时长；这些是另行命名的属性。

固定物理帧内推进逻辑。角色动画使用同一动作倍率；飞行物与持续区域按战斗时间运行。不要在每个技能随意设置 `Engine.TimeScale`，否则不同技能会互相覆盖，还可能让恢复停顿的计时器自己停住。

Godot `SceneTree.CreateTimer` 的暂停、物理帧和时间缩放参数需要显式考虑，尤其默认 `process_always` 的行为。这里的三时间域是本项目设计，并非引擎自动提供的完整战斗框架。[Godot SceneTree 官方文档](https://docs.godotengine.org/en/stable/classes/class_scenetree.html)

## 6. 命中和伤害结算合同

### 6.1 不把碰撞事件等同于伤害

命中收集先判断目标存活、阵营、受击层、范围与本次命中策略，再生成 `DamageRequest`。同一角色的多个 Hurtbox 必须归一为同一个 UnitId。

- 普攻/横扫：按 `(CastId, HitGroupId, TargetUnitId)` 去重，一次窗口内最多伤害一次。
- 两段攻击：两段使用不同 HitGroupId，可以各命中一次。
- 持续区域：按 `(EffectId, TickIndex, TargetUnitId)` 去重，每次 Tick 可命中一次。
- 判定开启时已在范围中的目标也必须被发现。S2 在物理帧统一收集重叠/形状查询结果，结合信号与去重处理；不要只依赖新进入事件。
- 突进和快速飞镖要检查上一位置到新位置的路径，不能仅靠终点重叠；碰墙按位移规则停止，不瞬移穿过碰撞体。

### 6.2 请求数据与结果分开

| 请求字段 | 用途 |
| --- | --- |
| RequestId / RootEventId / CastId / HitGroupId | 去重、定位本次技能、限制后置触发链 |
| SourceUnitId（可空）/ TargetUnitId | 支持陷阱与环境伤害；不强依赖攻击者节点还活着 |
| SkillId / SourceTags | 区分普攻、技能、持续、反伤、环境等来源 |
| SourceSnapshot | 提交时的技能等级、攻击属性、出伤倍率与暴击参数；独立飞行物不依赖已释放的来源节点 |
| DamageComponents | 每项有类型、数值、是否参与暴击等规则；首期只做物理与术法两类 |
| AttackOrigin / AttackDirection / IncomingDirection | 保存本次攻击的空间语义，供正面/背面判定 |
| DefenderFacingAtContact | 防御者在此次命中的朝向快照 |
| ForcedCritical / CriticalChance | 必暴标记与概率分离，不复用含糊的 `hitRate` 名称 |
| ControlPayload / OnHitEffects | 本次击退、硬直、待附加 Buff 等意图 |
| TriggerDepth / RemainingProcBudget | 防止反伤、击杀爆炸、附加伤害无限递归 |

`DamageResult` 记录各类型实际损伤、护盾吸收、减免、是否格挡/免疫、实际扣血、死亡和成功附加的控制。表现使用结果，不能看到原始请求就播“暴击成功”。治疗单独为 `HealRequest`；生命移除属于以后确有需求再引入的明确机制，不用负伤害偷偷实现。

### 6.3 首版固定结算顺序

1. 校验目标、队伍与重复请求，建立不可变空间快照。
2. 读取提交时保存的来源攻击快照，对一次伤害包进行一次暴击决策；被标记不参与暴击的分量保持原值。首期攻击与独立效果的来源攻击属性统一快照，目标防御与 Buff 按实际命中时读取；以后出现动态持续引导技能时再明确其每 Tick 取值规则。
3. 应用目标免疫、方向防守与各类型防御；物理和术法分别计算，不能把复合伤害先相加再只算一种抗性。
4. 汇总各类型结果，处理护盾，统一取整并得到非负生命伤害。
5. 原子提交生命变化；先判定死亡，死亡不能被同帧普通 Hurt 或移动命令覆盖。
6. 生成结果事件；按有效命中规则附加控制/Buff，死人不再接收普通控制。击杀与死亡奖励只结算一次。
7. 将反伤、吸血、击杀爆炸等后置效果放入队列，按顺序处理，不在 Buff 回调栈中同步递归调用结算器。

第一版公式可以使用 `基础分量 × 出伤倍率 × 方向倍率 × 100 / (100 + 对应防御)`，仅处理非负防御；护盾在分量结算后吸收总额。它是调参起点，不是已经选定的最终平衡模型。S1 先固定伤害，S2 只在实际技能需要时加入对应字段。

例如一次伤害含 30 物理 + 10 术法，目标物理防御 50、术法防御 0，无其他修正，则分量分别为 20 与 10，合计 30，再处理护盾。没有首期玩法需求时，不立刻添加火、雷、毒等多套抗性；火焰视觉可暂时映射术法伤害和燃烧 Buff。

### 6.4 方向快照

前摇可以允许有限转向；进入提交点后锁定本次攻击方向。刀光朝向、位移方向和判定方向使用同一份快照。命中时再记录目标朝向，用“目标朝向向量”与“目标指向来袭方向”的点积判断正面扇区。

近战来袭方向取该攻击窗口的攻击起点相对命中点的方向；飞行物取命中时速度的反向。方向长度接近 0 时使用已锁定攻击方向的反向作为回退。提交后的攻击者再转身，不会改变已经飞出的攻击的来袭角度；目标在命中前主动转身则可以改变防守结果。

### 6.5 受控反伤和触发链

反伤基于 **目标实际扣血**，不基于原始伤害或护盾吸收量；来源为空、来源无效、自伤、反伤和持续伤害默认不能触发。首版反伤不暴击、不吸血、不再次触发反伤。

后置请求保留 RootEventId，标记 `Reflected`，深度增加。建议每条根事件最多 4 层、32 个后置请求；超限记录开发日志并停止新增派生事件。后置处理前重新检查双方存活状态。效果触发器还应有自己的“每次命中/每次施法/每个根事件”策略；例如反伤每次有效直接命中触发，击杀奖励每个死亡实例只触发一次。

这组限制既能做出有趣组合，也能避免双方反伤、击杀爆炸或多重触发把一帧变成无穷循环。

## 7. Buff、控制权限、叠加与驱散

### 7.1 权限用聚合，不用恢复成 true

至少区分 `CanMove / CanAttack / CanCast / CanDodge / CanUseItem`。每个 Buff 提供自己禁止的权限，最终权限由所有有效来源聚合。一个眩晕结束后重新计算，不能直接执行 `CanMove = true`，否则会覆盖仍在生效的定身。

| 控制 | 禁止行为 | 不顺带禁止的行为 |
| --- | --- | --- |
| 眩晕 | 移动、普攻、施法、闪避 | 菜单和 UI 操作 |
| 沉默 | 主动施法 | 普攻、普通移动；闪避是否算技能单独设定，首版不算 |
| 定身 | 普通移动、位移型动作 | 原地普攻、非位移技能 |
| 缴械 | 普攻 | 普通移动与主动技能 |
| 减速 | 无直接禁止 | 调整移动倍率；不隐式减慢 UI 或 CD |

输入和 AI 读取同一份权限。位移型闪避会被定身禁止；受击牵引结束后权限立即释放，不能因“进入过 Hurt”延长隐藏硬直。

### 7.2 实例合同

每种 Buff 明确：来源、持续时间、最大层数、叠加键、同源重施规则、异源共存规则、Tick 周期、驱散类别、死亡/换图是否保留。建议首期仅提供三种叠加模式：刷新时长、叠层到上限、独立来源实例。

`OnAdded`、`OnStackChanged`、`OnTick`、`OnRemoved(reason)` 分开；移除原因区分到期、驱散、死亡、换图、替换。回调只能提交命令或后置效果，不能边遍历容器边直接增删同一容器。

驱散从 `None / Basic / Strong` 三档起步：不可驱散标记单独表达；基础驱散清除配置允许的减速/沉默，强驱散额外清除配置允许的定身/眩晕。治疗不默认驱散，死亡也不自动保留所有正面 Buff。

Boss 的控制抗性由目标定义控制持续倍率、哪些控制免疫以及保底最短响应时间。不要让同一种技能在 Boss 身上看起来完全无效却没有反馈；免疫时显示清楚的反馈，必要时转换成较短硬直或削弱，但转换必须写在规则中。

光环给进入范围的目标挂“由这个光环来源提供”的 Buff，离开时只移除该来源。重叠光环不误删对方加成；首期同名增益取最强，不无限叠加。低频范围刷新足够，不必每帧扫描全场全部节点。

任务系统订阅 `EnemyDefeated`、`SkillLearned`、`AreaDiscovered` 等已结算事件，记录任务实例自己的进度。任务不会因为驱散、死亡清 Buff 或换图而丢失。

## 8. 五个技能配置样例

这些是**原创招式设计提案**，借鉴的是“可读预警、位置博弈、条件触发和技能组合”的优点，不复刻现成技能名字、美术和音效。下面的距离用“角色身位”表达，实装再换算像素；不把现有精灵尺寸假定为最终尺寸。

下列“战意”消耗仅用于未来资源成本的调参样例。S1 只用 CD；S2 先令资源消耗为 0，验证现有机制。只有 S4 试玩证明单靠冷却无法形成选择时，才评估启用一条战意资源，不同时叠加体力与法力。

S1 固定为 **普攻 + 独立闪避 + 突进技能 + 横扫技能**，突进和横扫分别释放、分别记录 CD，不制作复合牵引技能。下列五个是 S2 起的组合扩展样例：先复用 S1 的位移和横扫验证“辕门折月”，再验证“回锋邀战”；守势、光环、反伤先用灰盒/测试单位验证，直到 S4 内容预算允许才进入正式地图。它们不会额外增加 S1 的技能与美术生产量。

### 8.1 辕门折月——突进后横扫，命中边缘奖励

- **ID / 用途**：`core.skill.lubu.fold_moon`；S2 吕布主动组合样例，复用 S1 两个独立技能 `core.skill.lubu.dash` 与 `core.skill.lubu.sweep` 已验证的突进、扇形判定和方向快照；S1 不提前制作此复合技能。
- **配置起点**：消耗 20 战意，CD 6 秒；前摇 0.18 秒，向锁定方向突进最多 2 身位/0.16 秒，横扫有效 0.12 秒，后摇 0.24 秒。
- **规则**：突进碰墙停止；横扫宽 150°、长 1.8 身位；突进本身不造成伤害，只算一次横扫 HitGroup。前摇结束锁定方向，提交成本和 CD，然后位移与横扫。
- **组合性**：S2 增加“戟尖”条件：目标距离横扫中心较远时附加短减速，近身只伤害。让玩家选择打满覆盖还是保留距离，不靠继续增加伤害数字堆变化。
- **反制**：敌人同版技能有清晰脚步与扇区预警，可以向侧面闪避；突进不自带全程无敌。
- **表现**：窄金白刀锋与暗红拖尾，命中瞬间停顿；刀光长度与真实扇区一致，不把地面预警遮住。
- **验收**：同一目标多个 Hurtbox 只扣一次；撞墙不穿越；转身不会让已提交刀光和伤害方向分离。

### 8.2 回锋邀战——牵引后留下明确逃脱窗口

- **ID / 用途**：`core.skill.weiyan.invite_duel.boss` 与 `.player`；S2 验证魏延招牌技能及吕布可习得变体，S1 不制作。
- **Boss 配置起点**：0.35 秒钩戟预警 → 0.18 秒短直线判定 → 被命中者被拉近最多 1.5 身位 → 0.65 秒蓄力 → 0.12 秒重劈 → 0.45 秒后摇；CD 8 秒。
- **公平性硬规则**：牵引自身不造成伤害；牵引结束立即解除该段移动控制。后续 0.65 秒允许玩家闪避或走出重劈区域，不追加隐形定身。重劈方向在蓄力开始时锁定，只允许前 0.15 秒轻微修正，随后不追着玩家转。
- **玩家版**：消耗 25 战意，CD 9 秒；牵引普通人形敌人，再执行短蓄力横劈。首期 Boss 对牵引位移免疫，但后续横劈仍可正常造成伤害，钩戟命中也要有清楚的免疫反馈；暂不为此新增架势条系统。
- **习得方式**：S2 测试场临时配置玩家版便于验收；S3 才做“识破魏延三次回锋并取胜”或剧情试炼后获得的学习流程，避免依赖尚未完成的任务系统。
- **效果组合**：直线命中 → 受碰撞约束的牵引 → 释放控制 → 蓄力 → 扇形伤害。牵引不能穿墙，目标中途死亡或离场则终止其牵引。
- **验收**：测试人员在牵引结束后有稳定操作窗口；闪避成功后重劈打空；提交前被打断不会生成孤立重劈。

### 8.3 横戟问路——正面守势存一次反击

- **ID / 用途**：`core.skill.lubu.gate_guard`；方向防守主动，S2 灰盒。
- **配置起点**：消耗 15 战意，CD 7 秒；前摇 0.10 秒，守势 0.75 秒，后摇 0.20 秒。守势期间正面 110° 内的直接伤害减少 60%，侧背面正常结算；移动减慢，不允许闪避取消后继续持有防守。
- **变化点**：成功防住一次直接攻击，获得仅能触发一次、持续 3 秒的“借势”。下一次普攻变成短促直刺，消耗借势；它不是把伤害原样反弹，仍走普通攻击流程。
- **实现范围**：方向减伤 Buff + 单次强化 Buff；不需要通用招架动画树。开始只对物理/术法直接伤害生效，不防地图陷阱和持续燃烧。
- **验收**：前后方命中结果不同；守势结束的同一帧按固定事件顺序计算；多段伤害不会叠出无限借势；死亡清除借势。

### 8.4 孤旌借风——站位光环与离阵一击

- **ID / 用途**：`core.skill.lubu.solitary_banner`；可由军营挑战获得的主动阵法，S2 验证区域/Buff 来源，S4 决定是否正式制作。
- **配置起点**：消耗 25 战意，CD 12 秒；0.30 秒插旗，旗阵半径 2.5 身位，持续 5 秒；同一释放者最多一面旗。
- **规则**：吕布在圈内获得 10% 动作加速，CD 不加速；主动离开旗阵时获得 2 秒“余风”，下一次突进距离提高少量，然后消耗。每面旗仅可给予一次余风，来回蹭边不能反复刷。
- **取舍**：留在阵里连续作战，或提早离阵追击；旗阵只辅助吕布，不要求实现伙伴编队。受击不会凭空重新生成光环实例。
- **表现**：脚下细线阵纹与轻薄风带；地面红色危险预警的对比度高于己方光环。色觉模式下靠线型和图案区分。
- **验收**：移出移入不重复奖励；旗阵消失只移除自己的加成；换图/死亡清理；换技能槽不能再放第二面旧旗。

### 8.5 披甲听雷——有上限、有条件的反伤被动

- **ID / 用途**：`core.passive.lubu.armor_echo`；被动候选，S2 验证后置结算；以后可作为精锐盾兵挑战奖励。
- **配置起点**：被直接攻击实际扣血后，在自身 2.5 身位内且仍存活的攻击者受到实际扣血量 20% 的术法反伤，单次最高 8，内置 CD 0.5 秒。
- **约束**：只有吕布本人仍存活才触发；不反射持续伤害、自伤、环境伤害、反伤；不暴击、不吸血，不附带其他 OnHit 触发。内置 CD 按被动 SkillId 记录，卸装重装不清空。
- **变化点**：它适合允许小幅受伤的压迫型打法，但没有纯挨打无脑收益；正面守势减轻实际扣血，也同时降低反伤量，玩家需要理解搭配的代价。
- **表现**：甲片短亮，短电弧指向来源即可，不制作全屏雷暴。
- **验收**：双方都拥有此被动时只产生一次派生反伤；完全吸收伤害不触发；击杀后不会给已经死亡的攻击者写生命。

### 8.6 技能收集与装备规则

首发内容提案为 **8–12 个主动技能、3 个被动候选**；这是总内容上限，不是每阶段都新增同等数量。稀有度与随机词条暂不加入，先用有清楚身份的招式和有限分支强化支撑搭配。

只有已解锁且可供玩家使用的 Definition 能装入技能槽。Boss 版与玩家版共享机制和表现资源时，可以共用基础配置，但保留独立 ID 与参数；不把 Boss 的召唤数量、全屏范围、剧情无敌直接授予玩家。

只在安全营地或客栈、脱离战斗且没有残留个人战斗效果时调整配装；战斗中不能换技能。营地配装不刷新 CD、战意和被动内置 CD。若“休息”允许统一恢复，它是另一个清楚标价/反馈的操作，不通过装卸技能偷偷实现。

S3 强化第一版每个核心技能只提供一个节点，例如辕门折月范围更宽；S5 有余量时再评估一个二选一分支，不提前要求完整技能树。强化后的参数由 `Definition + LearnedLevel + UpgradeChoice` 计算，不复制出一堆不可追踪的技能文件，也不在共享资源上原地加数值。

锻炼 S3 先做一课，首发最多三课：识破前摇、绕势破盾、聚势连招。按用户最新要求，连续现实 100 分钟未锻炼恢复 1 次收益机会，全部课程共用，离线计时；无收益复练重置休息计时。暂定本篇最多 3 次成长，每次初始基准 HP +2%、累计不超过 +6%，不复利。收益资格入场快照，永久增量、收益会话 ID、额度消耗与章节计数同一次提交；现实计时独立于战斗 TimeScale。完整契约见 [锻炼收益与实际时间](设计-锻炼收益与实际时间.md)。

## 9. 表现层：刀光、粒子、Shader 不决定伤害

S1 只先需要 `CastStarted / HitResolved / UnitDied / CastEnded` 等少量事件，S2 根据需求补 `TelegraphStarted / BuffChanged`。事件携带效果键、位置、方向、强度和归属，表现层选择资源播放。

同一技能可以替换刀光纹理、粒子数、声音或低配材质，命中形状和伤害结果保持一致。降低画质时保留预警、命中确认和角色轮廓；装饰粒子可以减少，危险范围不能变得看不见。

第一版反馈链建议固定：前摇动作/预警 → 清晰刀锋 → 命中闪白 + 轻击退/硬直 + 短音效 → 极短停顿 → 恢复动作。普通攻击与重击以幅度和时序区分，不让每一刀都震屏、慢动作、满屏粒子。Shader 用于闪白、轮廓、局部能量带；粒子用于火星、拖尾和阵法细节。

具体色板、比例、粒子预算与生图提示词由本目录风格文件统一。战斗附录只约束“反馈与判定一致”和“危险信息优先”。

## 10. 存档、内容包与平台边界

### 10.1 从 S3 开始就用稳定 ID

采用带命名空间的业务 ID，例如 `core.skill.lubu.fold_moon`、`core.map.start_village`、`dlc.north.skill.frost_banner`。显示名可以翻译或改名，文件可以移动，业务 ID 保持不变。不要把枚举下标、节点名、资源路径或 Godot 运行时实例编号当永久存档身份。

存档至少含：`SchemaVersion`、`GameVersion`、存档 ID、必要内容包版本、吕布成长、已学技能与强化、装备槽位、任务与世界标记、安全位置、设置。CD 若在可保存场景仍非零，保存剩余战斗秒数并在载入时恢复；不要靠存盘/换地图刷新。首期只在安全点保存，不要求中途保存完整技能时间线。

迁移以 DTO 版本逐级转换；写入先临时文件，再替换正式文件，并保留上一份有效备份。读取失败显示可理解的原因，不自动覆盖损坏文件。JSON 足以满足当前阶段，不为防作弊提前加自研加密和二进制协议。

### 10.2 DLC 先预埋约定，内容加载系统后做

S0–S2 只遵守稳定 ID 命名、资源边界；S3 存档写内容包 ID；S5 用一个本地测试扩展包验证缺失情况；S7 才制作正式 DLC 加载、分发与购买检查。

内容包清单建议含 `PackId / Version / MinimumGameVersion / Dependencies / EntryCatalog / LicenseOrEntitlementKey`。目录可以指向地图、技能、文本、图标、音效。先支持数据与资源包；新增 C# 行为随主程序更新发布，不承诺靠随意下载的代码即时扩展逻辑。

启动时先检查依赖与版本，再注册内容 ID；重复 ID 视为错误，不按加载顺序静默覆盖。基础包永远可用；包是否已下载与账户是否有资格使用是两个不同状态。开发测试内容的开关不等于正式环境获得 DLC 权益。

| 存档引用缺失内容 | 恢复策略 |
| --- | --- |
| 当前位置属于缺失地图包 | 回基础包安全营地，并提示缺失内容；保留原位置记录用于以后恢复 |
| 已学习技能定义缺失 | 保留原始 ID、等级和强化数据，界面显示不可用占位；从可操作槽位停用 |
| 槽位技能缺失 | 提供基础普攻/闪避，空出该主动槽，进入营地重新选择已知技能 |
| 任务、收藏或物品数据未知 | 保留原始记录并挂起相关进度，不当垃圾删除，不发重复奖励 |
| 存档版本高于当前程序 | 阻止覆盖与强行降级读取，提示用对应版本打开 |
| 包重新安装且版本兼容 | 重新解析保留的稳定 ID，恢复可用状态，不能重复发习得奖励 |

缺失内容恢复时先备份；用户确认继续后写新的恢复存档，原始存档不被静默覆盖。具体发布介质选型留到 S7，不需要 S1 先写一套 mod 平台。

### 10.3 `IPlatformServices` 与离线实现

游戏内的战斗、任务与本地存档不直接调用 Steam SDK。S3 起定义小型平台门面，S6 根据实际使用的适配库实现 Steam 版本；不需要为了“将来可能”把所有系统都抽象成接口。

| 能力 | `OfflinePlatformServices` | Steam 适配阶段 |
| --- | --- | --- |
| 平台可用状态 | 明确返回离线 | 上报可用/不可用/初始化失败 |
| 内容资格查询 | 基础包可用；开发配置只用于开发构建 | 查询对应 DLC 资格，与本地文件是否存在组合判断 |
| 成就提交 | 记录本地已达成；可标记待同步 | 幂等同步，重复打开游戏不重复计数 |
| 云存档能力 | 返回不支持，本地保存照常 | 接入选定的同步策略，冲突不静默覆盖 |
| 用户显示信息 | 本地配置档名称 | 平台信息只用于展示或平台关联，不作为唯一存档主键 |

Steam 客户端没启动、SDK 初始化失败或网络断开时，允许进入已获准可用的本地单机内容。实际授权细节遵循最终选用的 SDK 与商店配置；本条是可玩性目标，不是假设所有 DLC 都能无条件离线使用。

### 10.4 联机不在本轮排期

现在保留清晰的角色命令、结算结果、稳定内容 ID 和可记录的随机来源，是为了维护、测试和内容扩展；这些边界也可能对未来同步实验有用，但不因此实现网络层。当前不制作合作、PvP、服务器、匹配或网络回滚。

若用户以后改变范围，需要单独评估权威方、预测/纠正、位移与碰撞同步、随机数、掉线、跨版本、DLC 一致性、暂停与局部停顿规则，并重新设计相关系统。尤其单机暂停菜单与多人世界继续运行不能共享未经调整的假设。这个工作不归入 S7 的交付承诺，现有命令入口不等于即插即用联机。

### 10.5 S3 传送与 S5 坐骑的技术边界

“三仙”相关内容中，左慈本体与城池分身提供的传送，以及上下马，均属于世界命令，不塞进 Buff 或战斗技能。S3 传送需验证两端已解锁、对应地图内容可用且目标安全点有效；战斗中禁止传送，施法时不允许骑乘，入战自动下马，坐骑最多 2 只，只辅助赶路，不做马战。切图按“保存切图前内存快照并保留有效旧存档 → 取消施法与归属特效 → 清理旧地图 → 加载目标 → 验证安全落点 → 成功后更新存档”执行；失败则重新载入可用旧地图和旧位置，旧位置无效时回基础安全点，不留下半加载状态。传送和上下马都不刷新 CD、不重复发放课程/探索/任务奖励，也不复制持续技能实例。

## 12. 真正值得验证的边界场景

以下适合作为 S1–S3 的验收清单；数值计算和存档迁移可用自动检查，手感、预警和视觉同步必须在游戏里试。

1. 同一刀同时碰到同一个目标两个 Hurtbox，只扣一次；两段技能各扣一次；不同施法实例互不污染。
2. 前摇、有效帧和后摇分别触发死亡/眩晕/换图，旧判定都不会重新开启，角色不会永远锁定移动。
3. 命中帧转身、目标贴身与来自背后的飞镖，方向判定结果明确且重复一致。
4. 牵引结束后立即闪避，稳定避开后续重劈；被牵引到墙角时不穿墙、不进入无限控制。
5. 两个单位共享同一技能资源，一个进入 CD 或获得强化，另一个的状态与基础配置不变。
6. 同时受到眩晕和定身，眩晕结束后仍不可移动；单个光环结束不移除另一来源加成。
7. 双方反伤、护盾完全吸收、致死命中和来源已死亡都不会产生循环或重复奖励。
8. 打击停顿期间仍可打开菜单，停顿能结束；暂停不偷跑战斗 CD；动作加速不加速 Buff 持续计时。
9. 换槽、卸下重装、换图和载入存档不刷新 CD；营地配装不会复制持续效果或被动实例。
10. 缺失 DLC 后打开存档能回基础安全点，技能数据仍在；重新安装后能恢复，未知数据没有被覆盖清空。
11. 训练收益耗尽后连续现实 100 分钟未锻炼才恢复；无收益复练重置、离线恢复、换课共享额度、章节上限与重复结算均符合锻炼规则。
