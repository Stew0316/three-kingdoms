# 生图提示词模板 v0.1

> 日期：2026-09-28。用途：以后生成本项目的角色、场景、特效与图标时复用。当前只交付模板，没有生成图片，也没有已经批准的参考图。

## 1. 需求记录与使用原则

用户原始要求见 [2026.9.28 需求](../Prompt/2026.9.28.md)：

> 「帮我生成风格文件，我需要有一些风格文件，让以后你帮我生图的时候，风格保持统一。」

本模板服从 [美术与特效规范](风格-美术与特效规范.md)；暂定方向为斜俯视、32px 瓦片、普通角色 64 × 64 帧/44–48px 可见身高、约 3.5 头身、脚底锚点 `(32, 56)` 的像素画方案。先做 S0 样板后冻结，不默认项目现有图片已经符合此方案。

用户后续确认固定主角吕布、收集技能、单人 PvE，魏延为对手。生成重点是吕布一致性、敌人剪影和技能图标差异；不制作武将编队头像栏或招募界面素材。

新增需求记录：少量三国坐骑承接宠物的陪伴/赶路体验，普通马一匹、赤兔一匹候选，非战斗骑乘；左慈剧情解锁传送并在每城留一个分身；南华老仙、左慈、于吉采用本游戏原创传说化造型。以下附加模板随对应内容进入制作，不提前扩大 S0 样板范围。

提示词应由「固定风格前缀 + 一个资产模板 + 通用反向约束 + 本次参考图清单」组成。将尖括号中的占位内容替换成具体描述；每次只请求一个明确用途，不把立绘、世界精灵、技能图标和战斗截图混为一次产物。

生成模型可能忽略精确像素、透明通道、帧数、锚点、重复拼接和图集布局要求。文字约束用于减少偏差；正式像素资源仍需要在绘图工具里量化调色、人工修形、修帧、切片和验证。不要把「看起来像像素画的大图」直接视为可导入的真像素素材，也不要假设自动缩图就能得到一致轮廓。

## 3. 通用反向约束

```text
不要照片写实，不要 3D 渲染感，不要现代日式大头萌系，不要厚涂油画，不要摄影景深、虚焦、胶片颗粒、镜头光斑或全屏光晕；不要混杂大小不一的伪像素，不要抗锯齿造成的脏轮廓，不要模糊渐变填满人物，不要与参考图不同的俯角、头身比或光源。不要现代枪械、科幻机甲、欧洲板甲、现有商业作品标志或可识别的完整角色造型。不要文字、字母、数字、Logo、水印、签名、装饰边框、调色板标签、界面说明或多余对象；需要符号时使用原创几何图形。单资产请求不要生成海报、场景合成图、对比板或样机。透明背景必须是真实 Alpha，不要把棋盘格画进图片。不要切断武器、头顶、脚或特效边缘。不能满足精确尺寸、透明或帧要求时保留可整理的清楚源稿，不用伪装成已通过验收的资产。
```

当模板明确要求「角色设定板」或「无缝地块」时，按对应模板覆盖「单资产/透明背景」约束。不要让互相矛盾的背景、数量或布局要求同时存在。

```text
参考图：<R-UI-001 v1.0；实际附图>。
```

物品图标把「玩法核心」替换成「对象用途」，状态图标把「主体意象」替换成更简单的一个符号。不要在同一张图中同时给出三种用途。

技能卡由 UI 组件装配这张图标与本地化文本，生成图只提供主体图案和可复用的轻纹理装饰。技能名、核心描述、装备状态、锻炼进度、冷却数值与按键提示都不烘焙到图像中。三张技能卡并排时先检查剪影差异，不能只把同一个戟头换三种颜色代表不同能力。

## 9. 角色立绘与头像：单独路线

立绘使用下面专用前缀，**不叠加世界精灵的 64 × 64、像素轮廓、3.5 头身要求**。立绘服务对话、人物档案与宣传，不能直接裁成世界内精灵动画。与精灵一致的是角色身份、关键轮廓、颜色和装备，而不是渲染细节数量。

```text
项目 TK-ART v0.1 的人物立绘分支，原创三国汉末幻想角色。参考已批准游戏精灵，保持同一张脸的特征、发型、头巾或头冠、甲衣层级、主辅配色、武器和身份。采用简洁色块与少量手绘质感的国风人物插画，左上柔和主光，材质区分明确，轮廓清楚，避免照片写实、3D渲染和繁复油画笔触。自然略夸张的人物比例，约6头身；这是立绘，不是3.5头身世界精灵。
角色：<角色ID及身份>。表情：<平静但警觉>。姿态：<半身，右手扶住枪杆>。
用途与构图：<人物档案半身立绘，主体居中，四周留安全空间；后续可裁为256×256头像>。
目标源图：<1024×1536或其他本次尺寸>，真实透明背景，完整保留头部和关键武器轮廓；先以模型实际支持尺寸生成，再制作正式裁切版本。不要加入背景场景、文字、边框、Logo、署名、水印、界面组件或其他人物。
装饰细节不创造与批准精灵矛盾的新装备。参考图 <角色四向设定和已批准头像；实际附图>，角色身份参考优先于泛化画风联想。
```

对话头像至少验证中性、喜悦、严肃三种表情是否保持脸型；没有具体剧情需求时不先批量产出表情包。Steam 宣传图按届时明确的构图和上传规格另做，不把以上尺寸当作商店图规格。

## 10. 参考图、版本与复现记录

S0 先建立角色、地块与刀光草样；S4 才补齐自己制作或来源明确、允许使用的批准参考集：`R-CHR-001`（人物尺度与四朝向）、`R-ENV-001`（一屏场景与建筑视角）、`R-FX-001`（刀光/预警/光环对照）。图标和立绘开始制作时再补专用参考；坐骑开始时建立 `R-MOUNT-001`，左慈与传送内容开始时建立 `R-NPC-ZUOCI-001`、`R-TRAVEL-001`。这些 ID 是待制作清单，不代表文件已存在，不要求全部在 S0 完成。

每次生成至少附一个正确用途的批准参考，必要时再附当前对象的上一版。不要仅把磁盘路径写在提示词里却不实际提供图像。参考图优先级：**角色/对象身份参考 > 已批准同类资产 > 本文风格文字 > 泛化描述**。参考之间冲突时先选定有效版本，不能要求模型自行融合矛盾的角度与比例。

每批记录：

```text
batch_id: TK-20260928-001
asset_id: lubu
purpose: sprite
style_version: TK-ART-v0.1
palette_version: TK-P16-v0.1
reference_ids: R-CHR-001-v1.0（尚未制作时填写 none）
model_and_version: 实际工具能提供时记录，未知写 unknown
seed: 工具支持且返回时记录，不支持写 unavailable
prompt: 保存完整展开后的文字，不只保留模板名
requested_size / actual_size: 分别记录
alpha_checked / anchor_checked / palette_checked: true 或 false
source_file / edited_file / final_export: 分别记录
rights_notes: 自有参考、授权来源、其他待确认项

```

固定 seed（如果工具支持）只能帮助记录和部分复现，不能保证跨模型版本相同，更不能替代参考图与人工验收。新模型或重大参考图变更先重跑一名旧角色和一块旧地形，确认风格兼容后再做新内容。

## 11. 从生成候选到正式资产的验收流程

1. **身份检查**：服饰、武器、左右持握和颜色是否与批准版本一致；不能用「整体挺像」代替角色身份正确。
2. **视角和尺度检查**：放到同一屏的 32px 地块旁，核对身高、头身、建筑门宽和地面投影；原尺寸与整数倍都看。
3. **技术检查**：核实真实尺寸、Alpha、完整轮廓、脚底锚点、帧顺序、透明安全区；图集逐帧切开，不能只看整张缩略图。
4. **人工整理**：量化到批准色系、重画不一致像素簇和脏边、对齐接地点；源稿不合适时重做，不使用多次插值缩放掩盖问题。
5. **行为检查**：动画循环无脚滑与闪烁，攻击准备/生效/回收能辨识，刀光不越过预期语义范围；光环不会盖住人物或危险边界。
6. **场景检查**：黑底、白底、实际地图三个背景；图标缩到32px；危险信息在色觉模拟或灰度下仍有形状区分；标准/低档同一战斗对照。
7. **登记并冻结**：通过后标为 approved，保存源稿、编辑文件和导出版本。只有 approved 资产能作为下一批的风格参考。

验收失败的反馈应具体，例如「头部大了约 4px、光源变成右上、枪尖超出画布、脚底向右偏了 3px、黑底下有白边」；避免只写「更统一一点」「再精致一点」。同一对象优先在正确旧图上定点改动，每轮修改后重新核对完整轮廓。

此流程追求可重复的制作约束，不承诺任何模型能直接输出像素完美、全部动作一致或完全无缝的游戏资产。一次生成的好看程度与可用于战斗的资产质量，必须分别验收。
