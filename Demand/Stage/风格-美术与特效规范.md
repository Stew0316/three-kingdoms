# 美术与特效规范 v0.1

> 日期：2026-09-28。状态：待样板验证的制作提案，不代表现有资源已经符合本规范。阶段编号与本目录阶段总览一致。

> 2026-10-02 最新偏好：用户明确以 War3 式斜俯视和协调的行走、对打作为视觉参考，人物无需精细写实。动作主要在正常游戏尺寸与速度下验收，不默认要求复杂足部 IK、脚趾运动或布料模拟。详见 [动作制作标准问答](../Prompt/2026.10.02-War3式协调动作的制作标准.md)。下文像素尺寸与俯角仍为待验证提案，不能直接视为已确认的 War3 视觉规格；本次未改变二维运行架构。

## 1. 需求记录与设计边界

本文件响应用户「帮我完成这个阶段设计，设计出来的产物，放入到 /demand/stage 下」，以及 [原始需求](../Prompt/2026.9.28.md) 中以下内容：

> 「帮我生成风格文件，我需要有一些风格文件，让以后你帮我生图的时候，风格保持统一。」
>
> 「酷炫效果的话，我希望可以参考起凡群雄逐鹿的刀光，还有脚下的光环，还有 dota1 的光环……就是尽量参考一些老游戏的优点，然后我这个是 2d 游戏，因为我是一个人开发，尽量做的精致一点。」

用户后续确认：**主角固定为吕布，主要收集技能，不切换角色；仅做 PvE，魏延是对手**。因此目标是三国背景、以吕布游历、战斗、技能收集与搭配为核心的 2D 实时战斗 RPG。以下尺寸、颜色和资产预算是本项目建议值，不是 Godot 的强制要求。

用户新增要求记录：参考《魔女之泉》的宠物思路改为少量三国坐骑，名马不作为收集主轴；左慈在剧情节点解锁传送，每座城有一个分身；融合南华老仙、左慈、于吉。美术按本游戏的传说化角色表达，不作为史实考据结论。首发坐骑以普通马一匹为基础，赤兔一匹为候选；S5 才制作非战斗赶路骑乘，入战下马，不增加战斗宠物或骑乘作战动画。

风格关键词：**朴拙汉末、清晰剪影、沉静环境、锐利刀光、克制发光、少量精细重点**。历史纹样和幻想技能可以并存，但同一场景中不要同时混入写实照片、现代卡通、3D 渲染和粗细不同的像素块。

借鉴对象只用于分析「刀光有方向与力度」「脚底光环能表达持续状态」「技能轮廓能让玩家提前判断」等优点。角色造型、符号、纹样、图标、技能构图和音画素材均原创，不裁切或描摹现有商业游戏资产。

## 2. 现有资源审阅与风格冻结

已查看项目中的两个样本：

| 资源 | 观察 | 本阶段用途 |
| --- | --- | --- |
| `Source/City/三国志臣城池.png` | 有城名、路线与标识的策略地图，整体是旧纸与地形绘画风格 | 研究城池连接关系和地图信息层级；不能直接推导战斗资产规格 |
| `Source/Terrain/ground/ground.png` | 草地、土路、石块、灌木等图块，纹理较密，偏绘画质感 | 地面素材样本；先检查来源和原始切片参数，不直接当作 32px 像素标准 |

现有资源的授权、作者和制作规格尚未确认；「已在仓库」不等于「可用于商业发行」。来源登记属于后续制作验收，不在本次设计中判断授权结论。

**v0.1 推荐像素画路线**：人物与场景使用统一低分辨率像素绘制，特效以清晰像素轮廓和少量软光叠层辅助，UI 文字保持清晰。理由是方向、轮廓与颜色可以形成可检查的生产规则，并能复用动作和地块；像素画仍需要人工修帧，不假设它天然省时。

S0 只做一个角色静态样板、一块草地/土路与一个刀光草样，先验证视角、尺度与可读性；不在 6–12 小时准备期制作完整动作。S4 再补齐一屏场景、建筑角、光环、三个技能图标和 HUD 样板，记录修帧导入工时并冻结 v1.0 后批量生产。若绘画路线更省工且效果更好，应整体修订规格和参考图，不能只把部分角色改成另一种像素密度。

## 3. 视角、尺度与脚底锚点

| 项目 | v0.1 统一值 | 说明 |
| --- | --- | --- |
| 世界视角 | 固定斜俯视，正交式 2D 构图，能看到角色正面和物体顶面 | 类 RPG 的上下左右地图；不是 45° 菱形等距地图；无消失点 |
| 视觉俯角 | 约 45° 的统一观感 | 靠批准的角色、箱子、建筑参考图约束；不要求生图模型按文字精确求投影 |
| 世界基准画面 | 640 × 360 | 16:9；代表世界画面基准，不把所有 UI 文字画进低分辨率世界 |
| 展示策略 | 优先整数倍放大，保留像素边缘 | 1280 × 720 对应 2 倍、1920 × 1080 对应 3 倍；非整数窗口用留边或统一视口策略，S0 验证 |
| 基础瓦片 | 32 × 32 世界像素 | 坐标、道路、碰撞使用同一网格尺度；32 × 32 不意味着所有物件只占一格 |
| 普通人物单帧 | 64 × 64 透明画布 | 不含大型刀光与独立武器轨迹；所有动作保持画布尺寸 |
| 普通人物身高 | 44–48px，约 3.5 头身 | 头大到能辨认，仍能表现武将体态；武器、头冠可少量超出身体高度 |
| 人物脚底锚点 | 帧坐标 `(32, 56)`，左上为 `(0, 0)` | 待机时双脚接地中心；整套动画固定此位置，位移交给逻辑根节点 |
| 普通脚底碰撞 | 初始半径 8–10 世界像素的占地参考 | 按关卡通行实测调整；不使用整个人物画布当脚底占地 |
| 人形 BOSS | 可见身高约 56–64px，96 × 96 画布 | 锚点 `(48, 80)`；通常不超过普通人物高度的 1.4 倍，气势靠轮廓与动作 |
| 吕布骑乘组合（S5） | 96 × 96 画布，四朝向 | 接地中心锚点 `(48, 80)`；保持吕布原有头部与身体尺度，不放大骑手；与 BOSS 同画布不代表同一占地 |
| 地面影子 | 普通人约 24 × 10px，单独图层 | 椭圆、低对比，人物倒下或腾空时可以控制，不烘焙进人物帧 |
| 刀光与命中特效 | 常用 128 × 128 画布 | 原点默认 `(64, 64)`；记录实际中心、朝向和范围，不靠裁切猜测 |
| 脚底光环 | 128 × 128 画布，常用轮廓 64 × 32px | 原点 `(64, 64)`；地面圆的斜俯视视觉表现，不能当成逻辑距离公式 |
| UI 基准布局 | 1280 × 720 独立布局单位 | 文字以实际显示尺寸排版，不随世界像素化；与 640 × 360 世界坐标通过明确转换对应 |

32 世界像素约定为一个基础地块，不绑定真实米数。道路建议宽 3–5 格，主要交战区先用约 12 × 8 格的可活动空间验证。建筑门净宽至少 1.5–2 格，普通树冠约 2–3 格。尺寸是关卡原型起点，应以人物通行、闪避空间和摄像机视野调整。

角色、树木、建筑按落地位置考虑遮挡关系。高物件遮住玩家时，可降低遮挡部分透明度或使用清晰轮廓提示；不要让高饱和光环代替角色可见性。建筑先拆成地面底座和可遮挡上层，碰撞只覆盖实际不可通行区域。

移动与瞄准可以支持八方向或连续方向，美术先做下、上、左、右四个朝向；朝向变化设小范围稳定区以避免抖动。带盾、披肩、发型或武器左右不对称的角色，不能直接镜像后交付为另一个方向。暂不承诺八朝向全套动画。

色彩语义依靠「颜色 + 形状 + 动态」组合：敌方预警用朱红边界和向内收束线，友方辅助用青玉圆环与向上节奏，可交互点用金色小菱形。衣服颜色不能直接代表敌我，敌我通过独立标记区分。红绿色觉不敏感的玩家也应能通过边界、图标和填充纹理判断。

轮廓遵循角色强、前景次之、地面最弱：角色外轮廓以 1 世界像素深色为主，背光处允许 2px，内部少描边；草地和土路不逐格描黑边。禁止将非像素细线随意缩小后混入场景。高光使用连贯色块，普通地面不散布大量单像素亮点。地面亮度与饱和度低于角色和交互物，避免铺满纹理抢走注意力。

烘焙光照方向固定为左上，阴影偏右下。每种材质控制 3–4 个明暗层次：布料哑光、铁器短窄高光、木材大块顺纹、玉石少量透亮。统一光照优先于随机给每个人物换一个「更好看」的打光方向。昼夜和天气在 S4 后按预算增加，不在每一套基础贴图里各画一版。

## 5. 人物、装备与动画成本

主角和对手靠三项特征被识别：武器轮廓、头部/肩部轮廓、主辅色。吕布建议以原创方天戟、简化冠饰与短飘缨、暗甲配朱红识别；魏延用不同武器姿态、肩背轮廓与服饰色块区分，最终造型以批准样板为准。吕布冠饰与武器需一起纳入 64px 帧的安全区预算，不为了细长装饰随意改变角色身高；挥戟大范围轨迹作为独立特效。常规士兵可以共享身体动作、替换头部与服饰色块；BOSS 优先投入一个强识别动作和清晰蓄力姿势。避免普通士兵也拥有多层披风、飘带和独立布料动画。

初期使用逐帧像素角色方案。[RPG 设计](../Design/RPG设计.md) 中提到骨骼动画，把它保留为实现选项；不在 S1 同时维护骨骼和逐帧两条完整角色生产管线。装备数值可以丰富，外观换装在 S4 前只支持预先批准的有限形态；不能让一件新装备自动引出所有方向与动作的重画成本。

| 动作 | 单朝向初始帧数 | 关键要求 |
| --- | --- | --- |
| 待机 | 2 | 呼吸幅度小，脚底不漂移；可慢速循环 |
| 行走/跑步共用 | 4 | 明确落脚节奏；先通过速度调整服务移动原型 |
| 普通攻击 | 5 | 至少覆盖预备、出手、收招；刀光独立 |
| 受击 | 1 | 可以结合位移、短闪与僵直，不必先补多帧 |
| 倒地 | 4 | 第一帧衔接明确，末帧可停留 |
| 施法（S2 起） | 4 | 预备与释放姿态区分；技能复用此骨架 |
| 闪避（确有玩法需求时） | 3 | 方向与运动清晰；不靠残影隐藏本体 |

前五项合计 16 帧/朝向，四朝向为 **64 帧/基础人形**。施法与闪避都加入后为 92 帧/人形。共用动作和少量换色能够降低增量，但不能把 64 帧需求当作一次生图就能稳定完成。S4 记录一套完成、修帧、导入的实际工时，S5 内容规模据此回算。

每个技能先提供「预备 → 生效 → 回收」三个节拍的动作/特效标记。动画帧率和播放时长允许不同，不能用全体固定 FPS 取代节奏设计。技能逻辑时间轴是伤害、消耗和命中判定的依据，动画与特效读取对应事件；变速、打断和场景切换时不能出现动画已经停了但残留刀光继续伤人的情况。技能收集优先复用吕布的挥戟、刺击、施法等基础动作，凭轨迹、范围与节奏表达新能力，避免每解锁一个技能就新做一整套角色动画。

### 5.1 赶路坐骑的最小生产规格

普通马使用土褐、赭石和少量骨白，鞍具与吕布服饰统一；赤兔候选使用偏暖红棕毛色与不同鬃尾轮廓，主角敌我标记保持不变，不能靠永久烈焰或巨大光环表达稀有。坐骑不做宠物战斗面板、攻击、施法或骑乘受击整套动画。

骑乘组合采用 96 × 96 单帧，锚点 `(48, 80)` 为马匹四蹄围成区域的接地中心，轮廓四周至少留 2px。先做四朝向待机各 2 帧、赶路循环各 4 帧，合计 24 帧/坐骑外观；赤兔复用骨架与动作，但仍检查毛色、鬃尾和骑手遮挡。骑手与马可以分层制作，但首版按组合帧验收，逐方向校正骑手座位与武器收纳，不直接把步行吕布贴到马背上。

上下马先使用短转场与状态切换表达，进入战斗前恢复步行吕布、脚底影子与对应锚点。验收重点是上/下马前后的世界位置不跳动、四向骑手不滑动、马蹄节奏合理、城门与窄道不产生错误遮挡。碰撞和可骑乘道路由玩法/关卡定义，不能用 96px 画布大小当占地。

### 5.2 三仙与左慈分身

三仙同属项目世界观，先用不同剪影和道具建立辨识：南华老仙偏沉稳宽袍与古卷、左慈偏轻便云纹与拂尘、于吉偏朴素长衣与竹杖/葫芦。这些是可调整的原创造型方向，剧情职责以玩法副系统文档为准，不把传说外观写成历史事实。人物使用普通 64 × 64 帧、脚底 `(32, 56)`；优先待机和互动两组基础动作，不因身份为仙人就全部增大体型。

左慈本体与每城分身共用同一 NPC 造型及动作。分身增加少量青玉色局部边缘和独立的小符纹，不整体半透明到难以辨认；关闭装饰特效后仍有交互图标与本地化名称。城市差异由背景石台、灯笼、旗幡或植被体现，每城不重画一套左慈。

## 6. 刀光、光环与技能视觉语法

### 6.1 一次斩击的层次

一个基础重斩先只做四层：角色预备姿势 → 弧形刀锋主体 → 命中短闪 → 少量碎屑。刀光方向与实际挥砍方向一致，主体有清晰前缘和更淡的尾缘。锐利感来自弧线、粗细变化与短促时长，不能只靠全屏亮度提高。

建议起调范围：刀光主体约 80–140ms、尾迹约 100–180ms、命中亮点约 40–80ms；具体生效窗口以技能时间轴为准。普通攻击尽量只占附近战斗空间，超大扇形属于明确标识的特殊技能。上述数值是调参起点，不是所有招式的统一播放时长。

### 6.2 地面光环

光环位于脚底或范围地面，人物躯干不被环面盖住。友方持续状态使用一层细线轮廓和少量节律点，尽量让中心透明；敌方即将生效范围使用明确外边界与时间变化。纹样取自原创简化云纹、兵符、星点与几何结绳，避免直接搬用其他游戏的法阵图案。

「角色身上的状态光环」与「会影响整个区域的范围提示」必须区分。前者仅作身份/状态提示，不暗示半径；后者边界对应逻辑判定范围，并明确持续时间。地面视觉椭圆不自动改变世界中圆形判定，需要按既定世界坐标显示和实测对齐。

多状态叠加时，角色最多展示一个主光环加一个短时反馈；其余状态进入 HUD 图标。敌方致命预警始终保留。退出范围、效果驱散、场景切换、死亡和读档后，都应重新按有效状态决定显示，不能依赖旧动画自然播完来清理。

### 6.3 技能差异化

| 技能含义 | 主要形状和节奏 | 避免 |
| --- | --- | --- |
| 斩击/贯穿 | 扇形弧或窄长前锋，短促爆发 | 每把武器都画成同一条圆弧 |
| 投射物/连锁 | 可追踪的运动核心，分支落点清楚 | 铺满屏幕的连续白线 |
| 控制/束缚 | 足底闭合符号、明确边界、收紧动态 | 只换一个看不清的小颜色 |
| 护盾/减伤 | 局部外缘或短暂盾形闪现 | 永久盖住整个人物 |
| 恢复/增益 | 青玉向上粒点、细环节拍 | 与敌方地面危险使用相同填充 |
| 位移/幻影 | 短寿命轮廓残影，当前本体更实 | 让玩家找不到自己位置 |
| 终结技 | 先清晰蓄力，再集中高光，随后快速退场 | 用多种全屏叠层同时表达威力 |

特效语义优先级为：**敌方危险范围与时机 > 当前人物位置/受控状态 > 命中结果 > 我方技能轮廓 > 环境装饰**。层级的意思是可读性优先，不是把所有预警无条件画到人物头顶。

特效不决定伤害、碰撞或随机数。粒子、残影、屏幕扭曲只是表现消费者；关闭它们后技能结果、范围、预警时间与命中反馈仍一致。停顿、震屏、受击短闪允许独立降低或关闭，尤其不把高频整屏闪烁当作常规反馈。

### 6.4 左慈传送锚点

锚点地面装饰建议占 2 × 2 格，正式贴图 64 × 64，地面中心 `(32, 32)`；与左慈 NPC 分开导出和摆放。未解锁时使用低对比石纹，已解锁时增加青玉细线和小型金色交互菱形。可用、未开放、暂不可用必须有文本/形状差异，不能只改变亮度。

传送确认后的表现使用一次向上收束的细光和短淡出，到达时反向淡入；常用特效仍为 128 × 128。它不使用朱红范围边界、伤害式闪屏、反复爆闪或向内逼近的危险倒计时。低档保留静态锚点、交互图标与淡入淡出；地点加载和实际可用状态由玩法控制，不能因特效播完就认为传送已成功。每城复用同套效果，至多替换周边装饰。

## 7. HUD、菜单与多语言

菜单采用旧纸、墨线、暗铜的小面积装饰，信息底板保持平整。不能把书法和重纹理铺在技能说明或数值下方。纸张纹理用于边缘和留白区，战斗 HUD 更简洁。

战斗 HUD 建议包含：左上吕布生命与关键资源、下方已装备技能与冷却、右上任务一句话提示。敌方普通血条按需要显示；魏延等 BOSS 使用独立上方血条和阶段提示。只有一个可控主角，HUD 不预留武将队伍头像或换人操作。

技能收集页采用统一的技能卡组件：图标、技能名、一个核心作用句、释放条件/消耗、冷却、已装备标记、锻炼进度和下一次成长说明。边框、进度条和状态由 UI 绘制；卡片不生成成带文字的一整张图片。技能卡区分「已解锁」「装备中」「可锻炼」「待解锁」四种状态，状态变化同时有文字和形状提示。首次习得使用金色短闪与清晰的新技能卡，进度提升用小幅反馈，避免每次锻炼都播放占屏演出。

训练面板另显示全局收益额度、现实休息倒计时和章节成长上限；明确区分「本次可成长」「仅练习，会重计休息时间」「本阶段已达上限」。倒计时不是每张技能卡独立拥有的 CD，显示规则以 [锻炼设计](设计-锻炼收益与实际时间.md) 为准。

主按钮/技能图标制作 64 × 64 源图，32 × 32 缩略仍可辨识；HUD 中间留出战斗视野。图标只保留一个动作/对象主体，边框与冷却遮罩由 UI 统一生成，不画进每个图标。角色头像可由独立 256 × 256 正式头像裁切，不直接截取小尺寸世界精灵放大。

文字与边框分层，简中、繁中、日语、英文均使用文本资源。不要把城名、技能名、数字或按键文字烘焙进图片。UI 基准 1280 × 720 下，正文先以 20–24px 测试，次要文字不小于 18px；最终检查实际目标显示器可读性。给英文较长词句预留伸缩、换行和足够按钮宽度，避免只靠缩字号。字体必须记录来源、版本和许可，确认目标语言缺字处理；不在本文件指定未经核验的字体资产。

世界内血条、危险边界、交互提示和 HUD 不共享一张写死文字的贴图。菜单里的高精度立绘可以有更丰富笔触，但脸型、服饰、配色和武器必须与世界精灵一致；立绘不得反向决定每一帧都必须呈现的小装饰。

## 8. 导出、图集与资产身份

正式导出采用 RGBA PNG、真实 Alpha 透明背景。棋盘格、白底、黑底不等于透明；在深浅两种底色上检查白边、黑边和半透明杂点。保留编辑源文件与未经破坏的原始生成图，裁切修帧后的正式资源单独命名。

建议命名：`{类别}_{稳定ID}_{动作或用途}_{朝向}_{版本}.png`，使用小写英文与数字，例如 `chr_guard_spear_idle_s_v001.png`、`fx_crescent_slash_e_v001.png`、`tile_plain_grass_v001.png`。朝向使用 `n/e/s/w`，不适用时用 `none`。资源 ID 用于配置，不根据中文显示名变化；文件版本不进入存档身份。

优先每个「角色 + 动作」一张规则精灵图：普通人固定 64 × 64 单元，人形 BOSS 与骑乘组合按各自规格使用 96 × 96 单元，列为播放帧，四行按 `s, w, e, n` 排列。不同动作帧数分别记录，不能靠空白格推断结束。S1 可以先用逐帧 PNG 验证，再统一组图。未确认切片规则的 AI 图集只能作为草稿。

单独帧周围保留至少 2px 透明安全区；图集打包如需填充/外扩，由打包配置统一处理，不修改帧内锚点，也不让填充被算进逻辑帧尺寸。默认不自动去除透明边导致帧大小变化；若后续使用裁切打包，必须保存还原尺寸与偏移。像素世界资产使用保持硬边缘的采样方案，缩放与压缩在目标显示尺寸检查，具体 Godot 导入设置在 S0 实机确认。

每套正式资源至少记录以下字段，存储载体可先是随资源的说明文件，S2 再按项目资源系统落地：

```text
asset_id / style_version / palette_version / author_or_source / license_status
purpose: sprite | portrait | tile | effect | icon
frame_size / frame_count / directions / frame_durations_ms
pivot_px / visual_bounds / facing_default / pixels_per_tile
effect_events / loop / reference_ids / source_file / export_version
```

`effect_events` 记录应当响应的逻辑事件及特效节点位置，不能把「第 3 张图片看起来挥到敌人了」当作伤害系统接口。普通伤害区域不由图片透明度推导。

资源放回现有 `Source/People`、`Source/Terrain`、`Source/City` 等对应目录；特效和 UI 子目录待实际制作时再按项目目录规则增加。本轮只交付设计文件，不新建素材目录。未来增加 `Source` 第一级资源目录时同步更新项目 `AGENTS.md`。

## 9. 特效预算与低档降级

先建立可测量预算，再逐步增加画面层次。下面是 S2/S4 常规战斗的初始制作上限，属于试运行约束，不是某台电脑一定能达到的性能保证：同屏吕布 + 最多 8 个敌人（含 Boss），3 个危险范围同时提示；另以 12 个敌人的压力样例寻找瓶颈，与 S4 主文一致。

| 表现项 | 标准档起点 | 低档起点 | 必须保留 |
| --- | --- | --- | --- |
| 同时活跃粒子 | 全屏约 256，上限按实测调整 | 约 64，优先减少碎屑与环境粒子 | 危险边界不能依赖粒子绘制 |
| 当前人物残影 | 3 个以内 | 0–1 个 | 当前人物实体和方向 |
| 状态光环 | 每个角色 1 个主环 | 静态细环或状态图标 | 有效状态和敌我区分 |
| 命中反馈 | 刀锋 + 短闪 + 少量碎屑 | 刀锋 + 短闪 | 命中/未命中、受控/免疫差异 |
| 屏幕空间扭曲 | 默认关闭，特殊技能单独评估 | 关闭 | 相同的预警与伤害区域 |
| 全屏光效/震屏 | 可选，强度可调 | 关闭或降低 | 不以效果强度改变技能含义 |
| 环境风、水、落叶 | 少量复用贴图与材质 | 静态或停用 | 通路与可交互物仍可辨认 |

实施时优先复用贴图和材质、控制大面积透明叠加、限制短时对象数量，并按实际测量决定是否池化；「加 Shader」不等于「已经优化」。强扭曲、动态描边和多层半透明都有成本，必须用目标机器的帧时间检验。S4 选定最低目标机器，记录 CPU/GPU 帧时间、峰值特效数量及画质档位；未实测前不宣称具体最低配置。

低档与标准档都跑同一场战斗，逐项对照：敌方蓄力何时开始、边界在哪里、伤害何时生效、状态何时结束。不得通过删预警、改变判定或延后反馈来达成低档性能。

每批资源的通用验收：原尺寸和整数倍均检查；黑色、白色、实际草地三种背景上无脏边；角色四向比例一致；脚底锚点不漂移；连续播放不闪烁；图集帧数/顺序/时长可读；高低档可识别同一危险；来源与版本记录齐全。未通过的图保留为候选参考，不进入正式资产目录。
